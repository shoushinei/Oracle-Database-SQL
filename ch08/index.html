    第8章 副問合せ¶

    この章で問われる形

    • 「副問合せを使用する 必要がある のはどのレポートですか」
    • 「次の問合せについて正しい説明はどれですか」（< ALL、> ANY）
    • 「削除対象行が 複数行でも0行でもエラーにならない DELETE文はどれですか」
    • 「次のUPDATE文について正しい記述はどれですか」（相関副問合せ、SET句の副問合せ）

    8-1 副問合せを書ける場所¶

    判定基準

    場所 可否 備考
    WHERE / HAVING ✅ 最も一般的
    FROM（インラインビュー） ✅ 別名を付けて表のように使う
    SELECT リスト ✅ スカラー副問合せ（1行1列）のみ
    ORDER BY ✅ スカラー副問合せ
    CASE 式の中 ✅ スカラー副問合せ
    UPDATE の SET / WHERE ✅
    INSERT の VALUES / INSERT INTO ... SELECT ✅
    DELETE の WHERE ✅
    CREATE TABLE ... AS SELECT / CREATE VIEW ✅
    GROUP BY ❌
    1. 副問合せは かっこ で囲む
    2. WHERE句などの副問合せの中に ORDER BY は書けない（インラインビューでは可）
    3. 副問合せの中で GROUP BY・HAVING・結合は使える

    8-2 単一行副問合せ¶

    判定基準

    1. 単一行比較演算子 = <> > >= < <= の右には、1行を返す副問合せ しか置けない
    2. 副問合せが 2行以上 返すと 実行時エラー（ORA-01427）
    3. 副問合せが 0行 のときは エラーにならず、結果は NULL 扱い → 条件は不明 → 0行
    4. 単一行かどうかは「実際に何行返るか」で決まる（WHEREで主キーを指定していれば1行、など）
    -- 平均より給与が高い社員（AVGは1行）
SELECT last_name FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);             -- ✅

-- 部門ごとの平均は複数行 → = や > では使えない
SELECT last_name FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees GROUP BY department_id);   -- ❌ ORA-01427

-- 存在しない社員番号 → 0行 → エラーではないが結果も0行
SELECT last_name FROM employees
WHERE salary > (SELECT salary FROM employees WHERE employee_id = 99999);    -- ⚠️ 0行

    8-3 複数行副問合せ（IN / ANY / ALL）¶

    判定基準

    書き方 意味 言い換え
    IN (副問合せ) どれかと等しい = ANY
    NOT IN (副問合せ) どれとも等しくない <> ALL
    > ANY どれか1つより大きい 最小値より大きい
    < ANY どれか1つより小さい 最大値より小さい
    > ALL すべてより大きい 最大値より大きい
    < ALL すべてより小さい 最小値より小さい
    • ANY・ALLは単独では使えず、必ず比較演算子と組み合わせる（SOME は ANY と同じ）
    • 副問合せが 0行 のとき：ALL の条件は すべての行でTRUE、ANY は すべての行でFALSE
    • 複数行副問合せの演算子に 1行だけ の副問合せを使ってもエラーにならない

    salary < ALL (SH_CLERKの給与) の読み方

    「SH_CLERK の 全員より 低い」＝「SH_CLERK の 最低給与より 低い人」。 - 副問合せが複数行でも0行でも エラーにならない（ALLは複数行用） - 0行なら、ALLの条件は全行TRUEになり 全員が返る

    覚え方

    • ALL は「全員に勝つ／全員に負ける」→ 一番強い相手（最大）／一番弱い相手（最小）と比べる
    • ANY は「誰か1人に勝てばよい」→ 一番弱い相手（最小）に勝てばよい

    8-4 NOT IN と NULL¶

    判定基準

    1. NOT IN の副問合せが NULL を1行でも返すと、主問合せは0行
    2. IN の場合はNULLがあっても他の値で一致すれば返る
    3. 回避策：副問合せに WHERE 列 IS NOT NULL を付ける、または NOT EXISTS を使う
    -- 部下を持たない社員（manager_id に NULL が含まれると0行になる）
SELECT last_name FROM employees
WHERE employee_id NOT IN (SELECT manager_id FROM employees);            -- ⚠️ 0行

SELECT last_name FROM employees
WHERE employee_id NOT IN (SELECT manager_id FROM employees
                          WHERE manager_id IS NOT NULL);                -- ✅

    8-5 複数列副問合せ¶

    判定基準

    1. (列1, 列2) IN (SELECT 列a, 列b ...) のように 列の組 で比較できる（ペア比較）
    2. 左辺と副問合せの 列数・型が一致 していること
    3. 列を別々の副問合せで比べる（非ペア比較）と、結果が異なることがある
    SELECT last_name FROM employees
WHERE (department_id, salary) IN (SELECT department_id, MAX(salary)
                                  FROM employees GROUP BY department_id);   -- ✅ 部門ごとの最高給与の人

    8-6 相関副問合せ¶

    判定基準

    1. 副問合せの中で 主問合せの列（表別名）を参照 していれば相関副問合せ
    2. 主問合せの 1行ごとに 副問合せが評価される（最初に1回だけ実行されるのは非相関）
    3. 副問合せから外側の表別名を参照するのは 正しい書き方（エラーにならない）
    4. SELECT・UPDATE・DELETE のどれでも使える
    -- 自分の部門の平均より給与が高い社員
SELECT e.last_name, e.salary
FROM employees e
WHERE e.salary > (SELECT AVG(salary)
                  FROM employees
                  WHERE department_id = e.department_id);   -- ✅ e を参照 → 相関
    選択肢の言い回し 判定
    主問合せの表別名を参照しているので非相関副問合せである ❌
    副問合せが最初に1回だけ実行される ❌（行ごと）
    外側の文の表別名を参照しているため構文エラー ❌

    8-7 EXISTS / NOT EXISTS¶

    判定基準

    1. EXISTS (副問合せ) … 副問合せが 1行でも返ればTRUE
    2. SELECTリストの中身は何でもよい（SELECT 1、SELECT 'x'、SELECT *）
    3. 通常は 相関副問合せ で使う（相関がないと全行TRUE／全行FALSEになる）
    4. NOT EXISTS は副問合せのNULLの影響を受けない（NOT INとの違い）
    -- 部下がいる社員
SELECT m.last_name FROM employees m
WHERE EXISTS (SELECT 1 FROM employees w WHERE w.manager_id = m.employee_id);

-- 部下がいない社員（NULLがあっても正しく動く）
SELECT m.last_name FROM employees m
WHERE NOT EXISTS (SELECT 1 FROM employees w WHERE w.manager_id = m.employee_id);

    8-8 DMLでの副問合せ¶

    判定基準：「0行でも複数行でもエラーにならない」削除・更新

    WHERE句の形 副問合せが複数行 0行
    列 = (副問合せ) ❌ エラー 0行削除
    列 IN (副問合せ) ✅ ✅
    EXISTS (相関副問合せ) ✅ ✅
    NOT EXISTS (...) ✅ ✅（ただし意味は逆）

    「別表 blacklist に登録されている顧客を customers から削除」

    DELETE FROM customers c
WHERE customer_id IN (SELECT customer_id FROM blacklist);                  -- ✅

DELETE FROM customers c
WHERE EXISTS (SELECT 'x' FROM blacklist b WHERE b.customer_id = c.customer_id);  -- ✅

DELETE FROM customers c
WHERE customer_id = (SELECT customer_id FROM blacklist);                   -- ❌ 複数行でエラー

DELETE FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM blacklist b WHERE b.customer_id = c.customer_id); -- ⚠️ 逆（未登録者を削除）

    相関UPDATE¶

    UPDATE emp_copy w
SET salary = (SELECT salary FROM employees e WHERE e.employee_id = w.employee_id);
    1. 外側に WHERE がなければ emp_copy の全行 が更新対象
    2. 各行ごとに副問合せが実行される（相関）
    3. 対応する行がない社員は、副問合せが0行 → NULLで更新 される

    8-9 副問合せが必要になるとき¶

    判定基準

    1. 「集計した値（全体の平均・最大・最古など）と、個々の行を比べる／その行の他の列を表示する」→ 副問合せが必要
    2. 「グループごとの集計値を出すだけ」→ GROUP BY で足りる（副問合せ不要）
    3. 「単純な条件で絞るだけ」→ WHERE で足りる
    レポート 副問合せ 理由
    部門ごとの平均給与と最高給与 不要 GROUP BYだけ
    部門ごとの、職種が○○の社員数 不要 WHERE＋GROUP BY
    全社員の平均給与より高い社員の名前 必要 平均（集計値）と個人を比較
    最も入社日が古い社員の名前と入社日 必要 MIN(入社日)を求めてから、その人の名前を出す
    給与が最高の社員の部門 必要 同上

    集計関数とその行の列は同時にSELECTできない

    SELECT last_name, MIN(hire_date) FROM employees; は ❌（GROUP BYのルール違反）。 「最小値を持つ 人の名前」を出すには、副問合せで最小値を求めて WHERE で比べます。
