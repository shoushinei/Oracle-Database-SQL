# 第12章 DDLによる表の管理

!!! abstract "この章で問われる形"

    - 「制約に関して正しい記述はどれですか」「エラーを解消するには何のオプションを付けますか」
    - 「列の削除／未使用列について正しい記述はどれですか」
    - 「TRUNCATE について正しい記述はどれですか」

    - 「一時表／外部表について正しい記述はどれですか」

## 12-1 命名規則 { #naming }

<div class="rule-box" markdown>

**判定基準：表名・列名など（二重引用符なし）**

1. 長さは **1〜128バイト**（12.2以降。それ以前は30バイト）
2. **先頭は英字**
3. 使える文字は **英数字・`_`・`$`・`#`**
4. **予約語は不可**（`TABLE`、`SELECT`、`DATE`、`NUMBER` など）
5. 大文字小文字は区別されない（大文字で格納される）
6. **同じスキーマ・同じ名前空間** の中で重複できない
   - **表・ビュー・シーケンス・プライベートシノニム** などは同じ名前空間 → 同名不可
   - **索引・制約** はそれぞれ別の名前空間 → 表と同じ名前でもよい

**二重引用符で囲む** と、上の2〜5の制限がなくなる（ただし以後も必ず `"..."` で同じ表記で参照する）

</div>

| 名前 | 判定 | 理由 |
|---|---|---|
| `emp_2024` | ✅ | |
| `emp#1`、`emp$` | ✅ | `#` `$` は可 |
| `2024_emp` | ❌ | 数字で始まる |
| `emp-data` | ❌ | `-` は不可 |
| `emp data` | ❌ | 空白は不可 |
| `order` | ❌ | 予約語 |
| `"emp-data"` | ✅ | 引用符で囲めば可 |

## 12-2 DEFAULT（列のデフォルト値） { #default }

<div class="rule-box" markdown>

**判定基準**

1. 書く位置は **データ型の直後、制約より前**：`列 型 DEFAULT 式 [制約...]`
2. 指定できるもの：**リテラル、式、SQL関数**（`SYSDATE`、`USER` など）、シーケンスの NEXTVAL（12c以降）
3. 指定できないもの：**他の列**（ORA-00984）、`ROWNUM` などの疑似列、副問合せ
4. 値の型は列の型と合っていること
5. DEFAULTが使われるのは、INSERTで **列を省略したとき** か **`DEFAULT` キーワードを指定したとき**
   → **明示的に NULL を指定すると NULL が入る**（`DEFAULT ON NULL` を除く）
6. 後から DEFAULT を変更しても、**既存の行は変わらない**

</div>

```sql
reg_date  DATE DEFAULT SYSDATE NOT NULL,              -- ✅ DEFAULT → 制約の順
reg_date  DATE NOT NULL DEFAULT SYSDATE,              -- ❌ 順番が逆
status    VARCHAR2(10) DEFAULT 'NEW',                 -- ✅
short_nm  VARCHAR2(2) DEFAULT SUBSTR(name, 1, 2),     -- ❌ 他の列を参照
created   VARCHAR2(30) DEFAULT USER,                  -- ✅ SQL関数
```

## 12-3 制約の書き方 { #constraint-syntax }

<div class="rule-box" markdown>

**判定基準**

| | 列制約（インライン） | 表制約（アウトオブライン） |
|---|---|---|
| 書く場所 | 列定義の中 | 列定義の後（カンマで区切って） |
| 形 | `列 型 [CONSTRAINT 名] 制約` | `[CONSTRAINT 名] 制約 (列, ...)` |
| NOT NULL | ✅ **列制約でのみ** 書ける | ❌ |
| 複数列（複合キー） | ❌ | ✅ |
| 外部キー | `列 型 REFERENCES 親(列)`（**FOREIGN KEY は書かない**） | `FOREIGN KEY (列) REFERENCES 親(列)` |
| CHECK | **自分の列だけ** 参照できる | 同じ行の **複数の列** を参照できる |

- 1つの列に **複数の列制約** を並べてよい（`PRIMARY KEY NOT NULL`、`UNIQUE NOT NULL` も可）
- 制約名を省略すると `SYS_Cnnnnnn` という名前が付く
- 制約名は **スキーマ内で一意**

</div>

```sql
CREATE TABLE emp (
  emp_id   NUMBER(4)  CONSTRAINT emp_pk PRIMARY KEY,           -- ✅ 列制約
  email    VARCHAR2(50) UNIQUE NOT NULL,                       -- ✅ 複数の列制約
  dept_id  NUMBER(3)  REFERENCES dept(dept_id),                -- ✅ 列制約のFK
  mgr_id   NUMBER(4),
  salary   NUMBER(8)  CHECK (salary > 0),                      -- ✅ 自分の列だけ
  bonus    NUMBER(8),
  CONSTRAINT emp_mgr_fk FOREIGN KEY (mgr_id) REFERENCES emp(emp_id),   -- ✅ 表制約のFK
  CONSTRAINT emp_bonus_ck CHECK (bonus < salary)               -- ✅ 表制約なら複数列OK
);
```

```sql
dept_id NUMBER FOREIGN KEY REFERENCES dept(dept_id)            -- ❌ 列制約にFOREIGN KEYは書かない
bonus   NUMBER CHECK (bonus < salary)                          -- ❌ 列制約のCHECKで他の列
CONSTRAINT emp_nn NOT NULL (email)                             -- ❌ NOT NULLは表制約にできない
```

## 12-4 NOT NULL制約 { #not-null }

<div class="rule-box" markdown>

**判定基準**

1. **列制約としてのみ** 定義できる（表制約は ❌）
2. 後から追加するときは **`ALTER TABLE ... MODIFY`**（ADD CONSTRAINT ではない）
3. 既存の行にNULLがあると追加できない（ORA-02296）
4. DESCRIBEの「Null?」欄に表示される唯一の制約

</div>

```sql
ALTER TABLE emp MODIFY (email NOT NULL);                           -- ✅
ALTER TABLE emp MODIFY (email CONSTRAINT emp_email_nn NOT NULL);   -- ✅
ALTER TABLE emp ADD CONSTRAINT emp_email_nn NOT NULL (email);      -- ❌
```

---

## 12-5 UNIQUE制約・PRIMARY KEY制約 { #unique-pk }

<div class="rule-box" markdown>

**判定基準**

| | UNIQUE | PRIMARY KEY |
|---|---|---|
| 重複 | 不可 | 不可 |
| NULL | **可（何行でも）** | **不可** |
| 1表にいくつ | 複数 | **1つ** |
| 索引 | 一意索引を自動作成（既存の索引があれば流用） | 同左 |

</div>

---

## 12-6 FOREIGN KEY制約 { #fk }

<div class="rule-box" markdown>

**判定基準**

1. 参照先（親）は **主キーまたは一意キー** の列
2. 子の値は、親に **存在する値** か **NULL**
3. 親にない値を子にINSERT／UPDATE → ORA-02291
4. 子から参照されている親の行の削除は、オプションによって変わる

| 外部キーのオプション | 親の行を削除すると |
|---|---|
| （なし） | **エラー**（ORA-02292） |
| `ON DELETE CASCADE` | **子の行も削除** される |
| `ON DELETE SET NULL` | 子の外部キー列が **NULL** になる |

5. 子から参照されている親表は：
   - `DROP TABLE` → エラー（`CASCADE CONSTRAINTS` を付ければ、FK制約を削除して表を削除）
   - `TRUNCATE` → エラー（子が空でも）
6. 外部キーに **索引は自動作成されない**

</div>

---

## 12-7 CHECK制約 { #check }

<div class="rule-box" markdown>

**判定基準**

1. 各行が条件を満たすこと。ただし **条件が不明（NULL）なら違反にならない**
2. 参照できないもの：
   - **他の行**・**他の表**（副問合せ）
   - `SYSDATE`・`CURRENT_DATE`・`USER` などの関数
   - `ROWNUM`・`NEXTVAL`・`CURRVAL` などの疑似列
3. **列制約の CHECK は自分の列だけ** を参照できる（他の列は ORA-02438）。複数列は **表制約** で
4. 日付の定数を使うときは **4桁の年** まで完全に指定する（不完全だと ORA-02436）

</div>

```sql
salary NUMBER CHECK (salary BETWEEN 1000 AND 99999)                -- ✅
start_d DATE, end_d DATE, CHECK (end_d > start_d)                  -- ✅ 表制約
hire_date DATE CHECK (hire_date <= SYSDATE)                        -- ❌ SYSDATE不可
salary NUMBER CHECK (salary < (SELECT MAX(salary) FROM emp))       -- ❌ 副問合せ不可
```

## 12-8 制約の追加・無効化・削除 { #constraint-state }

<div class="rule-box" markdown>

**判定基準**

```sql
ALTER TABLE 表 ADD [CONSTRAINT 名] 制約 (列...);     -- 追加（NOT NULLはMODIFY）
ALTER TABLE 表 DISABLE CONSTRAINT 名 [CASCADE];      -- 無効化
ALTER TABLE 表 ENABLE [VALIDATE | NOVALIDATE] CONSTRAINT 名;  -- 有効化
ALTER TABLE 表 DROP CONSTRAINT 名 [CASCADE];         -- 削除
ALTER TABLE 表 DROP PRIMARY KEY [CASCADE];
```

1. 制約の追加・有効化（VALIDATE）は **既存データもチェック** する。違反があれば失敗
2. **有効な外部キーから参照されている主キー／一意キー** を無効化・削除するには **`CASCADE`** が必要
   - `DISABLE ... CASCADE` → 参照している **外部キー制約も無効化** される（削除はされない）
   - `DROP ... CASCADE` → 参照している **外部キー制約も削除** される
3. 主キー／一意キーを無効化すると、自動作成された **一意索引は削除** される（有効化で再作成）
4. `CASCADE` で無効化された外部キーは、主キーを有効化しても **自動では有効化されない**
5. `ENABLE NOVALIDATE` … 既存データはチェックせず、**以後の変更だけ** チェック
6. `DEFERRABLE INITIALLY DEFERRED` の制約は **COMMIT時** にチェックされる

</div>

| 「親表の主キーを無効化したらエラー。解消するには？」 | 判定 |
|---|---|
| `ON DELETE SET NULL` を付ける | ❌（外部キーの削除時の動作。無効化とは無関係） |
| `ON DELETE CASCADE` を付ける | ❌（同上） |
| `CASCADE` を付ける → 外部キーが **削除** される | ❌（DISABLEでは削除されない） |
| `CASCADE` を付ける → 外部キーも **同時に無効** になる | ✅ |

## 12-9 列の追加（ALTER TABLE ADD） { #alter-add }

<div class="rule-box" markdown>

**判定基準**

1. `ALTER TABLE 表 ADD (列 型 [DEFAULT ...] [制約...], ...)` … 複数列を一度に追加できる
2. 新しい列は **最後** に追加される（位置は指定できない）
3. **データがある表** に追加すると、既存の行の値は **NULL**（DEFAULTがあればその値）
4. したがって既存データがあるとき：

| 追加する列 | 判定 | 理由 |
|---|---|---|
| 制約なし | ✅ | 既存行はNULL |
| `DEFAULT 値 NOT NULL` | ✅ | 既存行にDEFAULTが入る |
| `NOT NULL`（DEFAULTなし） | ❌ | 既存行がNULLになり違反 |
| `CHECK (...)` | ✅ | NULLはCHECK違反にならない |
| `UNIQUE` | ✅ | NULLは何行でも可 |
| `PRIMARY KEY` | ❌ | 既存行がNULL |

5. 列数の上限は **1000**（**未使用列も数に含まれる**）

</div>

---

## 12-10 列の変更（ALTER TABLE MODIFY） { #alter-modify }

<div class="rule-box" markdown>

**判定基準**

| 変更内容 | データがあるとき |
|---|---|
| 文字列の長さ・数値の精度を **大きく** する | ✅ 常に可 |
| 文字列（VARCHAR2/CHAR）の長さを **小さく** する | 既存の値が **すべて収まれば** ✅ |
| **数値の精度・位取りを小さく** する | ❌ **列が全行NULLのときだけ** 可 |
| **データ型を変更** する | ❌ **列が全行NULLのときだけ** 可（CHAR⇔VARCHAR2は例外的に可） |
| **NOT NULL** を付ける | 既存の行に **NULLがなければ** ✅ |
| **DEFAULT** を設定・変更 | ✅（**以後のINSERTにだけ** 効く。既存のNULLは埋まらない） |

</div>

### 例：データ入りの表

| ID | NAME | EMAIL | SALARY |
|---|---|---|---|
| 1 | A | a@x.com | 100 |
| 2 | B | b@y.com | *(NULL)* |
| 3 | C | *(NULL)* | 108 |

（SALARY は `NUMBER(6)`、EMAIL は `VARCHAR2(15)`）

```sql
ALTER TABLE emp MODIFY (salary NUMBER(8));                         -- ✅ 精度を大きく
ALTER TABLE emp MODIFY (salary NUMBER(5));                         -- ❌ 値が入っている列の精度を小さく
ALTER TABLE emp MODIFY (email VARCHAR2(60));                       -- ✅ 長さを大きく
ALTER TABLE emp MODIFY (email VARCHAR2(10));                       -- ✅ 全値が10文字以内なら可
ALTER TABLE emp MODIFY (email VARCHAR2(60) DEFAULT 'TBD' NOT NULL);   -- ❌ 既存のNULL行（ID=3）があるのでNOT NULL不可
ALTER TABLE emp MODIFY (email DEFAULT 'TBD');                      -- ✅ 以後のINSERTだけ
ALTER TABLE emp ADD (status VARCHAR2(10) DEFAULT 'Active' NOT NULL);  -- ✅ 既存行にDEFAULTが入る
```

!!! warning "ADD と MODIFY で DEFAULT の効き方が違う"
    - **ADD** で `DEFAULT ... NOT NULL` → 既存行にもDEFAULT値が入るので **成功**
    - **MODIFY** で `DEFAULT ... NOT NULL` → 既存のNULLは埋まらないので、NULLがあれば **失敗**

## 12-11 列の削除（DROP）と未使用化（SET UNUSED） { #alter-drop }

<div class="rule-box" markdown>

**判定基準**

| | `DROP COLUMN` | `SET UNUSED` |
|---|---|---|
| 構文 | `DROP COLUMN 列` / `DROP (列1, 列2)` | `SET UNUSED COLUMN 列` / `SET UNUSED (列1, 列2)` |
| 複数列をまとめて | ✅ | ✅ |
| データ・領域 | **すぐに削除・解放** | **論理的に使えなくするだけ**（領域は残る） |
| 処理時間 | データ量に比例 | 速い |
| 列名の再利用 | ✅ | ✅（未使用列の名前は再利用できる） |
| 元に戻す | **不可**（DDL：ロールバック不可、ごみ箱にも入らない） | **不可**（ロールバック不可、戻すコマンドもない） |
| 1000列の上限 | 減る | **数に含まれたまま** |
| 後から領域を解放 | — | `ALTER TABLE 表 DROP UNUSED COLUMNS` |

- 表の **すべての列を削除することはできない**（最低1列は残る）
- 他の表の外部キーから参照されている列を削除するには `CASCADE CONSTRAINTS` が必要
- 未使用列は SELECT * や DESCRIBE に出てこない（`USER_UNUSED_COL_TABS` で数を確認）

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| 複数の列をまとめて未使用列に変更できる | ✅ |
| 1000列ある表で1列を未使用にすれば1001列目を追加できる | ❌（未使用列も数える） |
| SET UNUSED をロールバックすると未使用列を取り戻せる | ❌ |
| SET UNUSED を実行すると直ちに領域が再利用可能になる | ❌（DROP UNUSED COLUMNS が必要） |
| UNDOが残っていれば列の削除をロールバックできる | ❌ |
| 削除した列をごみ箱からリカバリできる | ❌ |
| 未使用に設定した列を使用可能に戻すことはできない | ✅ |

## 12-12 読取り専用表（READ ONLY） { #read-only }

<div class="rule-box" markdown>

**判定基準**

`ALTER TABLE 表 READ ONLY;`（戻すときは `READ WRITE`）

| できない ❌ | できる ✅ |
|---|---|
| INSERT / UPDATE / DELETE / MERGE | SELECT |
| **TRUNCATE** | 索引の作成・削除 |
| SELECT ... FOR UPDATE | 制約の追加・削除・有効化・無効化 |
| 列の追加・変更・削除・名前変更、SET UNUSED | 表の名前変更、**DROP TABLE** |
| FLASHBACK TABLE | ALTER TABLE MOVE、DROP UNUSED COLUMNS |

</div>

!!! warning "ひっかけ"
    「読取り専用表は削除できない」→ ❌（**DROP TABLE はできる**。データを変更する操作ではないため）

## 12-13 名前の変更・表の移動 { #rename-move }

<div class="rule-box" markdown>

**判定基準**

```sql
RENAME 旧表名 TO 新表名;                          -- 自分のスキーマのオブジェクトのみ
ALTER TABLE 旧表名 RENAME TO 新表名;
ALTER TABLE 表 RENAME COLUMN 旧列名 TO 新列名;
ALTER TABLE 表 RENAME CONSTRAINT 旧 TO 新;
ALTER TABLE 表 MOVE [TABLESPACE 表領域];           -- 表を再編成・移動
```

1. 表名を変えても、索引・制約・権限は **引き継がれる**。参照していたビューやシノニムは **無効** になる
2. `MOVE` すると行のROWIDが変わり、索引は **UNUSABLE** になる（`UPDATE INDEXES` や `ONLINE` 指定時を除く）

</div>

---

## 12-14 DROP TABLE / TRUNCATE TABLE / DELETE { #drop-truncate }

<div class="rule-box" markdown>

**判定基準**

| | `DELETE` | `TRUNCATE TABLE` | `DROP TABLE` |
|---|---|---|---|
| 分類 | DML | **DDL** | DDL |
| 消えるもの | 行（WHEREで指定可） | **全行**（WHERE不可） | 表そのもの（構造・データ・索引・制約・トリガー） |
| ロールバック | ✅ | ❌ | ❌ |
| 暗黙コミット | なし | **あり** | あり |
| ごみ箱（RECYCLEBIN） | — | **入らない**（戻せない） | **入る**（`PURGE` 指定時を除く） |
| 元に戻す | ROLLBACK | 不可 | `FLASHBACK TABLE 表 TO BEFORE DROP` |
| 索引 | 行に応じて更新 | **索引のデータも切り捨て** | 一緒に削除 |
| 領域 | 解放されない | **解放される**（HWMを下げる） | 解放（ごみ箱にある間は保持） |
| DELETEトリガー | 起動する | 起動しない | — |

- 子表から参照されている親表は **TRUNCATE も DROP もエラー**（DROPは `CASCADE CONSTRAINTS` で可）
- 他人の表を TRUNCATE するには `DROP ANY TABLE` システム権限が必要
- DROP TABLE しても、その表を参照する **ビュー・シノニムは残る**（無効になる）

</div>

| 選択肢の言い回し（TRUNCATE） | 判定 |
|---|---|
| WHERE句で切り捨てる行を指定できる | ❌ |
| ロールバックで切り捨てたデータを取り戻せる | ❌ |
| ごみ箱のデータを使って切り捨てたデータを取り戻せる | ❌ |
| 表に作成されている索引も同時に切り捨てられる | ✅ |

---

## 12-15 CREATE TABLE AS SELECT（CTAS） { #ctas }

<div class="rule-box" markdown>

**判定基準**

```sql
CREATE TABLE 新表 [(列名, ...)] AS SELECT ... ;
```

| 新しい表に引き継がれる ✅ | 引き継がれない ❌ |
|---|---|
| 列名・データ型（サイズ） | PRIMARY KEY / UNIQUE / FOREIGN KEY / CHECK 制約 |
| **データ（副問合せの結果の行）** | **索引** |
| **NOT NULL 制約** | **DEFAULT値** |
| | トリガー、権限 |

1. 列名リストを書くなら、列の数は副問合せの列数と **一致**。**データ型は書けない**
2. 列名リストを書かないなら、**式には列別名が必要**（ORA-00998）
3. **定義だけコピー** したいときは、行が返らない条件を付ける（`WHERE 1 = 2`）
4. LONG型の列はコピーできない

</div>

```sql
CREATE TABLE emp_copy AS SELECT * FROM employees;                         -- ✅ 全行コピー
CREATE TABLE emp_empty AS SELECT * FROM employees WHERE 1 = 2;            -- ✅ 構造だけ
CREATE TABLE emp_sal AS SELECT employee_id, salary*12 FROM employees;     -- ❌ 式に別名がない
CREATE TABLE emp_sal AS SELECT employee_id, salary*12 annual FROM employees;  -- ✅
CREATE TABLE emp_sal (id, annual) AS SELECT employee_id, salary*12 FROM employees;  -- ✅ 列名リスト
CREATE TABLE emp_sal (id NUMBER, annual NUMBER) AS SELECT ...;            -- ❌ 型は書けない
```

| 選択肢の言い回し | 判定 |
|---|---|
| コピー先は空の表として作成される | ❌（WHEREがなければ全行） |
| すべての行がコピーされる | ✅ |
| NOT NULL制約のみがコピーされる | ✅ |
| すべての制約がコピーされる | ❌ |

---

## 12-16 一時表 { #temp-table }

<div class="rule-box" markdown>

**判定基準：グローバル一時表（GTT）**

```sql
CREATE GLOBAL TEMPORARY TABLE 表 (...)
ON COMMIT { DELETE ROWS | PRESERVE ROWS };     -- 省略時 DELETE ROWS
```

| | DELETE ROWS | PRESERVE ROWS |
|---|---|---|
| データが消えるとき | **COMMIT時**（トランザクション終了） | **セッション終了時** |

1. **表の定義は永続的**。権限のあるユーザーの **全セッションから定義を参照できる**。セッションが終わっても定義は残る（DROP TABLE で削除）
2. **データは各セッション専用**。同じユーザーでも **別のセッションからは見えない**
3. DMLは **ロールバックできる**
4. **TRUNCATE できる**（自分のセッションのデータだけ消える）
5. 索引やビューを作成できる。外部キー制約は定義できない

**判定基準：プライベート一時表（18c以降）**

```sql
CREATE PRIVATE TEMPORARY TABLE ora$ptt_表 (...)
ON COMMIT { DROP DEFINITION | PRESERVE DEFINITION };   -- 省略時 DROP DEFINITION
```

1. 名前は **`ORA$PTT_` で始める**
2. **定義もデータも作成したセッションだけ** のもの（メモリ上）
3. `DROP DEFINITION` → トランザクション終了時に **表ごと** 消える。`PRESERVE DEFINITION` → セッション終了時に消える
4. 索引は作成できない

</div>

| 選択肢の言い回し（GTT・PRESERVE ROWS） | 判定 |
|---|---|
| セッション終了時に表定義も削除される | ❌（定義は残る） |
| SELECT権限を付与されたユーザーの全セッションから表定義を参照できる | ✅ |
| 同じユーザーの別のセッションから行データを参照できる | ❌ |
| 行ったトランザクションをロールバックできる | ✅ |
| TRUNCATEコマンドは実行できない | ❌ |

## 12-17 外部表 { #external }

<div class="rule-box" markdown>

**判定基準**

```sql
CREATE TABLE 表 (列 ...)
ORGANIZATION EXTERNAL (
  TYPE ORACLE_LOADER            -- または ORACLE_DATAPUMP（省略時 ORACLE_LOADER）
  DEFAULT DIRECTORY ディレクトリオブジェクト
  ACCESS PARAMETERS (...)
  LOCATION ('ファイル名')
)
[REJECT LIMIT n];
```

1. データは **OSのファイル** にあり、データベースには **定義（メタデータ）だけ** が格納される
2. **読取り専用**：**SELECTはできる** が、**INSERT / UPDATE / DELETE はできない**。索引も作れない
3. ファイルの場所は **ディレクトリオブジェクト** で指定（READ／WRITE 権限が必要）

| アクセスドライバ | 対応ファイル | ロード（読み込み） | アンロード（書き出し） |
|---|---|---|---|
| **ORACLE_LOADER**（**既定**） | テキスト（CSVなど） | ✅ | ❌ |
| **ORACLE_DATAPUMP** | 専用のダンプファイル | ✅ | ✅ |

4. `ORACLE_DATAPUMP` で `CREATE TABLE ... ORGANIZATION EXTERNAL (...) AS SELECT ...` とすると、
   **問合せ結果をダンプファイルに書き出し（アンロード）**、その外部表を作る
   → ダンプファイルを別のデータベースに移して、外部表として読み込める

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| デフォルトは ORACLE_LOADER アクセスドライバ | ✅ |
| ORACLE_LOADER を使うとデータのロードとアンロードが可能 | ❌（ロードのみ） |
| フラットファイル（CSV）をロードしたい場合は ORACLE_DATAPUMP を使う | ❌（ORACLE_LOADER） |
| 外部表に対して UPDATE 文を実行できる | ❌ |
| 外部表に対して SELECT 文を実行できる | ✅ |
| OS上のCSVファイルを、表にロードせずにSELECTで問い合わせできる | ✅ |
| OS上のCSVファイルを、表にロードせずにUPDATEで更新できる | ❌ |
| 複雑な問合せ結果をダンプファイルにアンロードして別DBに転送・ロードできる | ✅ |
| 複雑な問合せ結果をCSVファイルにアンロードできる | ❌ |
| `ORACLE_DATAPUMP ... AS SELECT` で外部表を作成し、ダンプファイルにデータを移入する | ✅ |
