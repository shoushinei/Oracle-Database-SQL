# 第5章 変換関数・NULL関数・条件式

!!! abstract "この章で問われる形"
    - 「何らかの **暗黙的な変換** が行われるものはどれですか」
    - 「NLS_DATE_FORMATが○○のとき、日数を計算するにはどの問合せを使いますか」
    - 「**正常に実行される**問合せはどれですか」（NULLIF・NVL・COALESCE の引数）
    - 「TO_CHARの結果として正しいものはどれですか」
    - 「CASE式／DECODEの結果はどれですか」

---

## 5-1 暗黙のデータ型変換 { #implicit }

<div class="rule-box" markdown>

**判定基準：Oracleが自動で変換するもの**

| 変換元 | 変換先 | 成功の条件 |
|---|---|---|
| 文字（VARCHAR2/CHAR） | 数値 | 文字列が **数値として読める** |
| 文字（VARCHAR2/CHAR） | 日付 | 文字列が **NLS_DATE_FORMAT に合う**（[5-2](#format-match)の柔軟な一致ルールあり） |
| 数値 | 文字 | 常に可 |
| 日付 | 文字 | 常に可（NLS_DATE_FORMATで文字にする） |

- 比較では **列の型に合わせて** リテラル側が変換されることが多い
  - 数値列 = `'5000'` → 文字が数値に変換される
  - 日付列 < `'31-MAR-05'` → 文字が日付に変換される
- 変換できない値なら **実行時エラー**（ORA-01722 無効な数値、ORA-01843 無効な月 など）

</div>

### 「暗黙的な変換が行われるもの」の見分け方

**両辺の型が同じか** を見ます。

| WHERE句（hire_date は DATE、salary は NUMBER） | 変換 |
|---|---|
| `salary BETWEEN 4000 AND 6000` | なし（数値と数値） |
| `salary = '5000'` | あり（文字 → 数値） |
| `hire_date < '31-MAR-05'` | あり（文字 → 日付） |
| `hire_date < DATE '2005-03-31'` | なし（日付リテラル） |
| `hire_date < TO_DATE('2005-03-31','YYYY-MM-DD')` | なし（明示的な変換） |

## 5-2 文字列を日付と解釈するときの一致ルール { #format-match }

<div class="rule-box" markdown>

**判定基準**（暗黙の変換・`TO_DATE` 共通）

1. **区切り記号は違ってもよい**（`-` の代わりに `/` や空白でも可）
2. 書式要素が一致しないとき、次の **読み替え** を試す
   | 書式の要素 | 代わりに受け付けるもの |
   |---|---|
   | `MM` | `MON`、`MONTH`（月名でもよい） |
   | `MON` | `MONTH`（月のフルスペルでもよい） |
   | `MONTH` | `MON` |
   | `YY` | `YYYY`（4桁年でもよい） |
   | `RR` | `RRRR`（4桁年でもよい） |
3. **`MON`（月名）の位置に数字の月は不可**（`MON` → `MM` の読み替えはない）
4. 時刻を省略すると 00:00:00
5. `FX` 修飾子を付けると、上の柔軟さがなくなり **完全一致** が必要

</div>

NLS_DATE_FORMAT＝`DD-MON-RR`、NLS_DATE_LANGUAGE＝`AMERICAN` の場合

| 文字列 | 日付に変換できるか | 理由 |
|---|---|---|
| `'31-MAR-05'` | ✅ | そのまま一致 |
| `'31-MAR-2005'` | ✅ | RR → 4桁年OK |
| `'31-MARCH-05'` | ✅ | MON → MONTH OK |
| `'31/MAR/05'` | ✅ | 区切り記号は違ってよい |
| `'31-03-2005'` | ❌ | MONの位置に数字の月は不可 |
| `'2005-03-31'` | ❌ | 並び順が違う |
| `'31-3月-05'` | ❌ | 言語がAMERICANなので日本語の月名は不可 |

## 5-3 TO_CHAR { #to-char }

<div class="rule-box" markdown>

**判定基準**

1. `TO_CHAR(日付 または 数値, '書式')` → **文字列** を返す
2. 書式は **単一引用符** で囲む。書式内の固定文字は **二重引用符** で囲む
3. 書式要素の **大文字小文字が出力に反映される**（`'MONTH'`→`MARCH`、`'Month'`→`March`）
4. `fm` を付けると、余分な空白・先頭ゼロを取り除く
5. 数値が書式の桁に収まらないと **`#` で埋められる**（エラーにはならない）

</div>

### 日付の主な書式要素

| 要素 | 意味 | 例 |
|---|---|---|
| `YYYY` / `YY` / `RR` | 年（4桁／2桁） | 2024 / 24 |
| `MM` | 月（数字） | 03 |
| `MON` / `MONTH` | 月名（略称／フル。MONTHは9文字に空白埋め） | MAR / MARCH |
| `DD` | 日 | 05 |
| `DY` / `DAY` | 曜日（略称／フル） | TUE / TUESDAY |
| `HH` / `HH12` / `HH24` | 時（12時間／24時間） | 03 / 15 |
| `MI` | **分**（`MM` は月なので注意） | 07 |
| `SS` | 秒 | 09 |
| `AM` / `PM` | 午前・午後 | PM |
| `"文字"` | 固定文字 | `"年"` |

```sql
TO_CHAR(hire_date, 'YYYY-MM-DD')                 -- '2024-03-05'
TO_CHAR(hire_date, 'fmMonth DD, YYYY')           -- 'March 5, 2024'
TO_CHAR(hire_date, 'YYYY"年"MM"月"DD"日"')       -- '2024年03月05日'
TO_CHAR(hire_date, 'YYYY年MM月DD日')             -- ❌ 固定文字に二重引用符がない
TO_CHAR(SYSDATE, 'HH24:MM:SS')                   -- ⚠️ MM は「月」。分なら MI
```

### 数値の主な書式要素

| 要素 | 意味 |
|---|---|
| `9` | 数字（先頭のゼロは表示しない） |
| `0` | 数字（先頭のゼロも表示する） |
| `$` / `L` | ドル記号／ローカル通貨記号 |
| `.` / `D` | 小数点 |
| `,` / `G` | 桁区切り |
| `MI` | 負の数の符号を後ろに |
| `PR` | 負の数を `< >` で囲む |

```sql
TO_CHAR(1234.567, '9,999.99')     -- ' 1,234.57'（小数は四捨五入、先頭は符号用の空白）
TO_CHAR(1234, '099999')           -- ' 001234'
TO_CHAR(12345, '999')             -- '####'（桁あふれは # 表示。エラーではない）
TO_CHAR(0.5, '9.99')              -- '  .50'
TO_CHAR(0.5, '0.99')              -- ' 0.50'
```

## 5-4 TO_DATE / TO_NUMBER と日付リテラル { #to-date }

<div class="rule-box" markdown>

**判定基準**

| 関数 | 変換 | ポイント |
|---|---|---|
| `TO_DATE(文字列 [, '書式'])` | 文字 → 日付 | 書式省略時は NLS_DATE_FORMAT。**文字列と書式が一致しないとエラー** |
| `TO_NUMBER(文字列 [, '書式'])` | 文字 → 数値 | `'$1,234'` のような文字は書式が必要 |
| `DATE 'YYYY-MM-DD'` | 日付リテラル | **書式は固定**（NLS設定に左右されない）。時刻は00:00:00 |

- 数値と日付の **直接の変換関数はない**（文字を経由する）

</div>

### 「ある日から今日までの日数」を求める判定

日付 − 日付 ＝ 日数。**両方とも日付型** になっているかを確認します。

```sql
SELECT SYSDATE - TO_DATE('2020-10-31', 'YYYY-MM-DD') FROM dual;   -- ✅ 日付 − 日付
SELECT SYSDATE - DATE '2020-10-31' FROM dual;                     -- ✅
SELECT SYSDATE - TO_CHAR('2020-10-31', 'YYYY-MM-DD') FROM dual;   -- ❌ TO_CHARは文字を返す
SELECT SYSDATE - TO_DATE('2020-10-31', 'DD-MON-RR') FROM dual;    -- ❌ 文字列と書式が一致しない
```

!!! warning "ひっかけ"
    `TO_DATE` の書式は「**変換元の文字列がどう書かれているか**」を表すもの。
    NLS_DATE_FORMAT（表示形式）に合わせる必要はありません。

## 5-5 RR書式（2桁の年の世紀） { #rr }

<div class="rule-box" markdown>

**判定基準**

| 現在の年の下2桁 | 指定した2桁が 00〜49 | 指定した2桁が 50〜99 |
|---|---|---|
| **00〜49** | **今世紀** | **前世紀** |
| **50〜99** | **次世紀** | **今世紀** |

- `YY` は **常に今世紀**
- 4桁で書けば、そのままの年

</div>

2026年に実行した場合

| 文字列 | `RR` | `YY` |
|---|---|---|
| `'15'` | 2015 | 2015 |
| `'95'` | **1995** | **2095** |

## 5-6 NVL { #nvl }

<div class="rule-box" markdown>

**判定基準**

1. `NVL(式1, 式2)` … 式1がNULLなら **式2**、そうでなければ **式1**
2. 戻り値は **式1の型**。式2は式1の型に **変換できなければエラー**

</div>

```sql
NVL(commission_pct, 0)                    -- ✅ 数値と数値
NVL(TO_CHAR(commission_pct), 'なし')      -- ✅ 文字と文字
NVL(commission_pct, 'なし')               -- ❌ 'なし' を数値に変換できない（ORA-01722）
NVL(hire_date, SYSDATE)                   -- ✅
NVL(hire_date, '未定')                    -- ❌ '未定' を日付に変換できない
```

!!! tip "集計と組み合わせる"
    `AVG(commission_pct)` と `AVG(NVL(commission_pct, 0))` は分母が違うため結果が変わります。→ [6章](ch06.md#agg-null)

---

## 5-7 NVL2 { #nvl2 }

<div class="rule-box" markdown>

**判定基準**

1. `NVL2(式1, 式2, 式3)` … 式1が **NULLでなければ式2**、**NULLなら式3**
2. 式2と式3は **互換性のある型** であること
3. 式1の型は何でもよい（判定に使うだけ）

</div>

```sql
NVL2(commission_pct, salary + salary*commission_pct, salary)   -- ✅ 数値と数値
NVL2(commission_pct, 'あり', 'なし')                            -- ✅ 文字と文字
NVL2(commission_pct, 'あり', 0)                                 -- ✅ 0 は文字 '0' に変換できる
NVL2(commission_pct, 0, 'なし')                                 -- ❌ 'なし' を数値に変換できない
```

!!! note "式2と式3の型"
    式3は **式2の型に合わせて** 変換されます。「式2の型に式3を変換できるか」で判定します。

## 5-8 NULLIF { #nullif }

<div class="rule-box" markdown>

**判定基準**

1. `NULLIF(式1, 式2)` … 2つが **等しければNULL**、等しくなければ **式1**
2. **式1にリテラルの `NULL` は書けない**（❌ ORA-00932）
3. 2つの引数は **両方数値**、または **同じデータ型** でなければならない
   → **数値と文字の組合せは暗黙変換されずエラー**

</div>

| SQL | 判定 | 結果／理由 |
|---|---|---|
| `NULLIF(10, 100)` | ✅ | 10（等しくない → 式1） |
| `NULLIF(10, 10)` | ✅ | NULL |
| `NULLIF('10', 'A')` | ✅ | `'10'`（文字どうし） |
| `NULLIF(NULL, 10)` | ❌ | 式1にNULLリテラル |
| `NULLIF(10, 'A')` | ❌ | 数値と文字 |
| `NULLIF(10, NULL)` | ✅ | 10 |

## 5-9 COALESCE { #coalesce }

<div class="rule-box" markdown>

**判定基準**

1. `COALESCE(式1, 式2, ..., 式n)` … 左から見て **最初のNULLでない値** を返す。全部NULLならNULL
2. 引数は **2つ以上**、個数の上限は事実上なし（NVLは2つ固定）
3. すべての引数が **同じデータ型グループ** であること（数値どうしはOK。数値と文字の混在は ❌）

</div>

```sql
COALESCE(commission_pct, salary, 0)              -- ✅ すべて数値
COALESCE(TO_CHAR(commission_pct), 'なし')        -- ✅ すべて文字
COALESCE(commission_pct, 'なし')                 -- ❌ 数値と文字
```

## 5-10 CASE式 { #case }

<div class="rule-box" markdown>

**判定基準**

```sql
-- 単純CASE：式と値の「等しい」比較だけ
CASE 式 WHEN 値1 THEN 結果1 [WHEN 値2 THEN 結果2 ...] [ELSE 結果] END

-- 検索CASE：任意の条件
CASE WHEN 条件1 THEN 結果1 [WHEN 条件2 THEN 結果2 ...] [ELSE 結果] END
```

1. 最後は **`END`**（SQLでは `END CASE` は ❌）
2. 上から評価し、**最初に一致した WHEN** の結果を返す
3. `ELSE` を省略して一致しなければ **NULL**
4. すべての結果（THEN・ELSE）は **同じデータ型グループ**（数値と文字の混在は ❌）
5. **単純CASEの WHEN に条件（`> 100` など）は書けない**
6. 単純CASEでは NULL と NULL は一致しない（`CASE x WHEN NULL` はヒットしない）

</div>

```sql
CASE job_id WHEN 'IT_PROG' THEN 1.1 WHEN 'SA_REP' THEN 1.2 ELSE 1 END        -- ✅
CASE WHEN salary < 5000 THEN 'LOW' WHEN salary < 10000 THEN 'MID' ELSE 'HIGH' END  -- ✅
CASE salary WHEN > 10000 THEN 'HIGH' END                                     -- ❌ 単純CASEに条件
CASE WHEN salary > 10000 THEN 'HIGH' ELSE 0 END                              -- ❌ 文字と数値
CASE WHEN salary > 10000 THEN 'HIGH' END CASE                                -- ❌ END CASE
```

## 5-11 DECODE { #decode }

<div class="rule-box" markdown>

**判定基準**

1. `DECODE(式, 検索値1, 結果1 [, 検索値2, 結果2 ...] [, デフォルト])`
2. 等しい比較のみ（単純CASEと同等）。デフォルト省略で一致しなければ **NULL**
3. **DECODEでは NULL と NULL は一致する**（CASEとの違い）
4. Oracle独自の関数

</div>

```sql
DECODE(job_id, 'IT_PROG', salary*1.1, 'SA_REP', salary*1.2, salary)
DECODE(commission_pct, NULL, 'なし', 'あり')   -- NULLの行は 'なし'（DECODEはNULL同士が一致）
```
