# 第6章 集計関数とGROUP BY

!!! abstract "この章で問われる形"
    - 「**正常に実行される**問合せはどれですか」（GROUP BY と SELECT の整合、WHEREの集計関数）
    - 「**実行してエラーにならない**問合せはどれですか」（集計関数のネスト）
    - 「次の問合せで返される値について正しい説明はどれですか」（COUNTの違い）
    - 「次の2つの問合せについて正しい記述はどれですか」（GROUP BYの有無と行数）

---

## 6-1 集計関数の種類と引数の型 { #aggregate }

<div class="rule-box" markdown>

**判定基準**

| 関数 | 使える型 | NULL |
|---|---|---|
| `SUM(式)` / `AVG(式)` | **数値のみ** | 無視 |
| `MAX(式)` / `MIN(式)` | **数値・文字・日付** | 無視 |
| `COUNT(式)` | 何でも | 無視 |
| `COUNT(*)` | — | **NULLの行も数える** |
| `STDDEV` / `VARIANCE` | 数値のみ | 無視 |

- 集計関数は **複数行をまとめて1つの値** を返す（単一行関数との違い）
- `DISTINCT` を引数の前に付けると、重複を除いてから集計する（`ALL` は既定）

</div>

```sql
SELECT MAX(hire_date), MIN(last_name) FROM employees;   -- ✅ 日付・文字もOK
SELECT SUM(hire_date) FROM employees;                   -- ❌ SUMは数値のみ
SELECT AVG(last_name) FROM employees;                   -- ❌ AVGは数値のみ
```

## 6-2 COUNTの3形態 { #count }

<div class="rule-box" markdown>

**判定基準**

| 書き方 | 数えるもの |
|---|---|
| `COUNT(*)` | **すべての行**（NULLを含む行も、重複行も） |
| `COUNT(列)` | 列が **NULLでない** 行 |
| `COUNT(DISTINCT 列)` | 列の **NULLでない値の種類数** |

- 0件のときも `COUNT` は **0** を返す（NULLではない）

</div>

### 例で確認

| ID | NAME | TEAM |
|---|---|---|
| 1 | Ann | X |
| 2 | Bob | Y |
| 3 | Cid | *(NULL)* |
| 4 | Dan | X |
| 5 | Eve | Y |
| 6 | Fay | X |

| 式 | 結果 | 理由 |
|---|---|---|
| `COUNT(*)` | **6** | 全行 |
| `COUNT(name)` | **6** | NULLなし |
| `COUNT(team)` | **5** | NULLの1行を除く |
| `COUNT(DISTINCT team)` | **2** | X と Y（NULLは種類に数えない） |

## 6-3 集計関数とNULL { #agg-null }

<div class="rule-box" markdown>

**判定基準**

1. `COUNT(*)` 以外の集計関数は **NULLを無視** する
2. **AVGの分母は「NULLでない行数」**
3. NULLを0として扱いたいなら `NVL(列, 0)` で包んでから集計する
4. 対象行が0行のとき：`COUNT` → **0**、`SUM`・`AVG`・`MAX`・`MIN` → **NULL**

</div>

commission_pct が `0.2, 0.4, NULL, NULL` の4行

| 式 | 計算 | 結果 |
|---|---|---|
| `SUM(commission_pct)` | 0.2+0.4 | 0.6 |
| `AVG(commission_pct)` | 0.6 ÷ **2** | 0.3 |
| `AVG(NVL(commission_pct, 0))` | 0.6 ÷ **4** | 0.15 |
| `COUNT(commission_pct)` | | 2 |
| `COUNT(*)` | | 4 |

## 6-4 GROUP BY のルール { #group-by }

<div class="rule-box" markdown>

**判定基準**

1. **SELECTリストにある「集計関数以外の列・式」は、すべて GROUP BY に書かれていなければならない**（ORA-00979 / ORA-00937）
2. 逆に、GROUP BY の列を SELECT に書かなくてもよい
3. GROUP BY に **列別名は使えない**（列名・式で書く）。数字を書いても **列位置としては解釈されない**（ORDER BYとの違い）
4. GROUP BY に書けるのは列・式（集計関数は書けない）
5. 複数列を書くと、その **組合せ** ごとにグループ化される

</div>

```sql
SELECT department_id, COUNT(*) FROM employees GROUP BY department_id;               -- ✅
SELECT COUNT(*) FROM employees GROUP BY department_id;                              -- ✅ GROUP BY列はSELECTになくてよい
SELECT department_id, job_id, SUM(salary) FROM employees GROUP BY department_id, job_id;  -- ✅
SELECT job_id, COUNT(*) FROM employees GROUP BY department_id;                      -- ❌ job_id がGROUP BYにない
SELECT department_id, COUNT(*) FROM employees;                                      -- ❌ GROUP BYがない
SELECT department_id dept, COUNT(*) FROM employees GROUP BY dept;                   -- ❌ 別名は不可
```

!!! tip "SELECT と GROUP BY の照合手順"
    1. SELECTリストから **集計関数の中にない列** を全部書き出す
    2. それが **すべて GROUP BY にある** か確認する
    3. 1つでも漏れていたら ❌

## 6-5 WHERE と HAVING { #having }

<div class="rule-box" markdown>

**判定基準**

| | WHERE | HAVING |
|---|---|---|
| 絞り込む対象 | **グループ化する前の行** | **グループ化した後のグループ** |
| 集計関数 | **使えない**（ORA-00934） | 使える |
| 書く位置 | FROMの後 | GROUP BYの後（※） |

1. HAVING には **集計関数** または **GROUP BY の列** を書く
2. HAVING の集計関数は **SELECTリストになくてもよい**
3. GROUP BY なしで HAVING を書くと、表全体を1グループとして扱う

※ Oracleは HAVING を GROUP BY の前に書いても受け付けますが、試験では「GROUP BY → HAVING」を正として判断してください。

</div>

```sql
SELECT department_id, COUNT(department_id)
FROM employees
WHERE commission_pct IS NOT NULL           -- 行の条件はWHERE
GROUP BY department_id
HAVING COUNT(department_id) > 4;           -- ✅ グループの条件はHAVING

SELECT COUNT(department_id) FROM employees
WHERE commission_pct IS NOT NULL AND COUNT(department_id) > 4   -- ❌ WHEREに集計関数
GROUP BY department_id;

SELECT department_id FROM employees
GROUP BY department_id HAVING MAX(salary) > 10000;    -- ✅ MAXはSELECTになくてよい
```

## 6-6 集計関数のネスト { #nesting }

<div class="rule-box" markdown>

**判定基準**

1. 集計関数のネストは **2レベルまで**（3レベルは ❌）
2. ネストするときは **GROUP BY が必須**（ORA-00978）
3. ネストした集計関数と一緒に **単独の列（GROUP BY列も含む）をSELECTに書けない**（ORA-00937）
4. 結果は **1行**（内側の集計でグループごとの値を出し、外側でそれをまとめる）

</div>

```sql
SELECT MAX(AVG(salary)) FROM employees GROUP BY department_id;               -- ✅ 部門平均の最大値（1行）
SELECT MAX(AVG(salary)) FROM employees;                                      -- ❌ GROUP BYがない
SELECT department_id, MAX(AVG(salary)) FROM employees GROUP BY department_id;  -- ❌ 単独の列と併用
SELECT MAX(MIN(AVG(salary))) FROM employees GROUP BY department_id;          -- ❌ 3レベル
SELECT AVG(MIN(salary)) FROM employees;                                      -- ❌ GROUP BYがない
```

!!! warning "単一行関数のネストとは別ルール"
    単一行関数は何重でもネストできます。「2レベルまで」は **集計関数** の制限です。
    集計関数の中に単一行関数を入れる（`AVG(NVL(commission_pct,0))`）のはネストのレベルに数えません。

## 6-7 返る行数 { #rows }

<div class="rule-box" markdown>

**判定基準**

| 問合せ | 返る行数 |
|---|---|
| 集計関数あり・**GROUP BYなし** | **常に1行**（0件の表でも1行） |
| GROUP BY あり | **グループ数**（0件なら0行） |
| 集計関数のネスト（GROUP BY あり） | 1行 |
| GROUP BY なし ＋ HAVING で条件不成立 | 0行 |

</div>

```sql
-- 文1：GROUP BYなし → 常に1行
SELECT AVG(salary * 12) FROM employees;

-- 文2：GROUP BYあり → job_idの種類数だけ行が返る
SELECT AVG(salary * 12) FROM employees GROUP BY job_id;
```

| 選択肢の言い回し | 判定 |
|---|---|
| 文1は常に1行だけ結果を返す | ✅ |
| 文2は常に1行だけ結果を返す | ❌ |
| 文1と文2の出力は常に同じ | ❌ |
| 文1／文2はエラーになる | ❌ |
