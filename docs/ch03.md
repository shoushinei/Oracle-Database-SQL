# 第3章 検索条件とソート・置換変数

!!! abstract "この章で問われる形"
    - 「NULLで…NULLでない行を表示したい。適した問合せはどれですか」
    - 「2文字目が○で、その後に3文字以上続く名前を抽出したい。どの問合せですか」
    - 「次のスクリプトを3回実行しました。置換変数は何回入力を求められましたか」
    - 「SET VERIFY ON について正しい記述はどれですか」
    - 「ORDER BY について正しい記述はどれですか」

## 3-1 WHERE句の基本 { #where }

<div class="rule-box" markdown>

**判定基準**

1. `WHERE` は `FROM` の直後。**行** を絞り込む
2. 文字・日付の値は `'...'` で囲む。**文字の比較は大文字小文字を区別** する
3. 日付を文字で書くと **NLS_DATE_FORMAT に合わせた暗黙の変換** が行われる（→ [5章](ch05.md#implicit)）
4. **列別名は使えない**（ORA-00904）
5. **集計関数は使えない**（ORA-00934）→ `HAVING` を使う

</div>

```sql
SELECT * FROM employees WHERE last_name = 'King';     -- ✅
SELECT * FROM employees WHERE last_name = 'KING';     -- ⚠️ エラーではないが 'King' はヒットしない
SELECT * FROM employees WHERE last_name = King;       -- ❌ King は列名扱い
SELECT * FROM employees WHERE AVG(salary) > 5000;     -- ❌ 集計関数は WHERE 不可
```

## 3-2 比較演算子 { #comparison }

| 演算子 | 意味 | 判定 |
|---|---|---|
| `=` | 等しい | ✅ |
| `<>` `!=` `^=` | 等しくない | ✅（3種類とも可） |
| `>` `>=` `<` `<=` | 大小 | ✅ |
| `=<` `=>` `><` | — | ❌ 存在しない |

!!! warning "NULLとの比較はエラーにならない"
    `WHERE commission_pct = NULL`、`WHERE commission_pct <> NULL`、`!= NULL` は **すべて構文的にはOK**。
    ただし結果は「不明」になり **1行も返りません**（⚠️）。NULLを探すなら [IS NULL](#null-condition)。

---

## 3-3 LIKE条件 { #like }

<div class="rule-box" markdown>

**判定基準**

1. ワイルドカードは **2つだけ**
   - `%` … **0文字以上** の任意の文字列
   - `_` … **ちょうど1文字** の任意の文字
2. `?` や `*` は **ワイルドカードではない**（ただの文字として扱われる）
3. 大文字小文字は区別する
4. `%` や `_` 自体を検索したいときは `ESCAPE '文字'` でエスケープ文字を指定する

</div>

### パターンの読み方

| パターン | 意味 |
|---|---|
| `'A%'` | Aで始まる |
| `'%a'` | aで終わる |
| `'%a%'` | どこかにaを含む |
| `'_a%'` | 2文字目がa（全体は2文字以上） |
| `'_a___'` | 2文字目がaで、**全体がちょうど5文字** |
| `'_a___%'` | 2文字目がaで、その後に **3文字以上** 続く（全体5文字以上） |
| `'%\_%' ESCAPE '\'` | `_` という文字を含む |

!!! tip "「〜以上」と「ちょうど」"
    `_` を並べた数は **ちょうどその文字数**。「以上」にしたいなら **最後に `%`** を付けます。
    `'_a___'` と `'_a___%'` の違いがよく問われます。

```sql
SELECT * FROM employees WHERE job_id LIKE 'SA\_%' ESCAPE '\';   -- ✅ 「SA_」で始まる
SELECT * FROM employees WHERE job_id LIKE 'SA_%';               -- ⚠️ 「SA」＋任意1文字で始まる（SAXも該当）
SELECT * FROM employees WHERE first_name LIKE '?a*';            -- ⚠️ ? と * はただの文字
```

## 3-4 IN条件 { #in }

<div class="rule-box" markdown>

**判定基準**

1. `列 IN (値1, 値2, ...)` は `列 = 値1 OR 列 = 値2 OR ...` と同じ
2. リストにNULLを書いても、NULLの行はヒットしない（`= NULL` になるため）
3. **`NOT IN` のリストにNULLが1つでもあると、1行も返らない**

</div>

```sql
SELECT * FROM employees WHERE department_id IN (10, 20, NULL);      -- 10と20の行だけ
SELECT * FROM employees WHERE department_id NOT IN (10, 20, NULL);  -- ⚠️ 0行
```

!!! note "なぜ NOT IN + NULL は0行か"
    `NOT IN (10, 20, NULL)` ＝ `<> 10 AND <> 20 AND <> NULL`。
    最後の `<> NULL` が常に「不明」なので、AND全体が TRUE になる行がありません。
    副問合せで同じことが起きる例 → [8章 NOT INとNULL](ch08.md#not-in-null)

## 3-5 BETWEEN条件 { #between }

<div class="rule-box" markdown>

**判定基準**

1. `BETWEEN 下限 AND 上限` … **両端を含む**（`>= 下限 AND <= 上限`）
2. **下限を先に書く**。逆に書くとエラーにはならないが **0行**
3. 数値・文字・日付のどれにも使える

</div>

```sql
WHERE salary BETWEEN 4000 AND 6000     -- ✅ 4000以上6000以下
WHERE salary BETWEEN 6000 AND 4000     -- ⚠️ 0行
WHERE last_name BETWEEN 'A' AND 'C'    -- ✅ 'C'ちょうどは含むが 'Cole' は含まない（'Cole' > 'C'）
```

## 3-6 NULL条件（IS NULL） { #null-condition }

<div class="rule-box" markdown>

**判定基準**

| 書き方 | 判定 |
|---|---|
| `列 IS NULL` | ✅ NULLの行 |
| `列 IS NOT NULL` | ✅ NULLでない行 |
| `NOT 列 IS NULL` | ✅ （条件全体の否定。IS NOT NULLと同じ結果） |
| `列 NOT IS NULL` | ❌ 構文エラー（語順が違う） |
| `列 = NULL` / `列 <> NULL` / `列 != NULL` | ⚠️ 実行できるが0行 |
| `列 IS NOT = NULL` など | ❌ |

</div>

!!! example "「commission_pctがNULLで、department_idがNULLでない行」"
    ```sql
    SELECT * FROM employees
    WHERE commission_pct IS NULL AND department_id IS NOT NULL;   -- ✅
    ```
    `= NULL` や `<> NULL` を含む選択肢は、エラーにはならなくても **目的の行が返らない** ので不正解です。

## 3-7 AND / OR / NOT と優先順位 { #logical }

<div class="rule-box" markdown>

**判定基準：演算子全体の優先順位**（上ほど先）

1. 算術演算子（`*` `/` → `+` `-`）
2. 連結演算子 `||`
3. 比較条件（`=` `<` `>` …）
4. `IS [NOT] NULL`、`LIKE`、`[NOT] IN`
5. `[NOT] BETWEEN`
6. 不等号（`<>` `!=`）
7. **`NOT`**
8. **`AND`**
9. **`OR`**

→ 論理演算子は **NOT → AND → OR** の順。変えたいときは `( )`

</div>

```sql
-- AND が先に評価される
WHERE job_id = 'SA_REP' OR job_id = 'AD_PRES' AND salary > 15000
-- ＝ job_id = 'SA_REP' OR (job_id = 'AD_PRES' AND salary > 15000)

-- OR を先にしたいならかっこ
WHERE (job_id = 'SA_REP' OR job_id = 'AD_PRES') AND salary > 15000
```

### NULL（不明）を含む論理演算

| | 結果 |
|---|---|
| TRUE **AND** 不明 | 不明（返らない） |
| FALSE **AND** 不明 | FALSE |
| TRUE **OR** 不明 | **TRUE（返る）** |
| FALSE **OR** 不明 | 不明 |
| **NOT** 不明 | 不明 |

## 3-8 ORDER BY句 { #order-by }

<div class="rule-box" markdown>

**判定基準**

1. **文の最後**（FETCHがあればその前）に書く
2. 指定方法は **列名・列別名・式・列位置（1から）** のどれでもよく、混在も可
3. **SELECTリストにない列** でもソートできる（ただし DISTINCT・集合演算・GROUP BY の場合は制限あり）
4. 既定は **ASC（昇順）**。`ASC`／`DESC` は **列ごとに** 指定する
5. 列位置はSELECTリストの列数を超えられない（ORA-01785）

</div>

```sql
SELECT last_name, salary*12 annual FROM employees ORDER BY annual DESC;      -- ✅ 別名
SELECT last_name, salary*12 annual FROM employees ORDER BY 2 DESC;           -- ✅ 位置
SELECT last_name, salary*12 annual FROM employees ORDER BY salary*12;        -- ✅ 式
SELECT last_name FROM employees ORDER BY hire_date;                          -- ✅ SELECTにない列
SELECT last_name FROM employees ORDER BY 2;                                  -- ❌ 列は1つしかない
SELECT last_name, salary FROM employees ORDER BY salary DESC, last_name;     -- ✅ salary降順、同額はlast_name昇順
```

!!! warning "ひっかけ"
    `ORDER BY department_id, salary DESC` の `DESC` は **salaryだけ** に効く。department_idは昇順のまま。

### データ型ごとの昇順

| 型 | 昇順の並び |
|---|---|
| 数値 | 小さい → 大きい |
| 日付 | 古い → 新しい |
| 文字 | 文字コード順（英大文字 → 英小文字） |
| NULL | **最後**（最大値扱い） |

## 3-9 NULLのソート位置 { #nulls-order }

<div class="rule-box" markdown>

**判定基準**

1. NULLは **最大値** とみなされる
   - `ASC`（昇順）→ NULLは **最後**（既定で `NULLS LAST`）
   - `DESC`（降順）→ NULLは **最初**（既定で `NULLS FIRST`）
2. `NULLS FIRST` / `NULLS LAST` で明示的に変更できる

</div>

```sql
ORDER BY commission_pct                    -- NULLは最後
ORDER BY commission_pct DESC               -- NULLは最初
ORDER BY commission_pct DESC NULLS LAST    -- 降順だがNULLは最後
```

## 3-10 行制限句（FETCH / OFFSET） { #fetch }

<div class="rule-box" markdown>

**判定基準**

```text
ORDER BY ...
[OFFSET n {ROW | ROWS}]
[FETCH {FIRST | NEXT} [n | n PERCENT] {ROW | ROWS} {ONLY | WITH TIES}]
```

1. **ORDER BYの後** に書く
2. `FIRST` と `NEXT`、`ROW` と `ROWS` は **どちらでも同じ意味**
3. `OFFSET n ROWS` … 先頭n行を飛ばす
4. `WITH TIES` … 最後の行と **ソートキーが同じ値の行も含める**（ORDER BY が前提）
5. `n PERCENT` … 全体の行数に対する割合

</div>

```sql
SELECT last_name, salary FROM employees
ORDER BY salary DESC
FETCH FIRST 5 ROWS ONLY;                      -- 給与上位5行

SELECT last_name, salary FROM employees
ORDER BY salary DESC
OFFSET 5 ROWS FETCH NEXT 5 ROWS ONLY;         -- 6〜10位

SELECT last_name, salary FROM employees
ORDER BY salary DESC
FETCH FIRST 3 ROWS WITH TIES;                 -- 3位と同額の人も含む（4行以上もありうる）
```

!!! warning "ROWNUMとの違い"
    `WHERE ROWNUM <= 3 ORDER BY salary DESC` は「**先に3行取ってから** ソート」。上位3件にはなりません。

## 3-11 置換変数（& と &&） { #substitution }

<div class="rule-box" markdown>

**判定基準**

| 書き方 | 入力を求められるタイミング | 値の保持 |
|---|---|---|
| `&変数` | **出てくるたびに毎回**（同じ文に2回あれば2回、実行するたびに毎回） | 保持しない |
| `&&変数` | **最初の1回だけ** | セッション中ずっと保持（`UNDEFINE` するまで） |

1. `&&` で一度値が決まった変数は、その後 `&変数` と書かれても **入力を求められない**
2. 文字・日付の値は `'&変数'` のように引用符で囲む（または入力時に引用符を付ける）
3. 列名・表名・条件・ORDER BYなど、**SQL文のどこにでも** 使える
4. SQL*Plus と SQL Developer の機能（データベースではなくツール側で置換）

</div>

### 入力回数の数え方

スクリプト `SELECT &x, &y FROM &&z;` を同じセッションで **3回** 実行（DEFINE/UNDEFINEなし）

| 変数 | 1回目 | 2回目 | 3回目 | 合計 |
|---|---|---|---|---|
| `&x` | 入力 | 入力 | 入力 | **3回** |
| `&y` | 入力 | 入力 | 入力 | **3回** |
| `&&z` | 入力 | （保持値） | （保持値） | **1回** |

```sql
SELECT &col FROM employees ORDER BY &col;    -- 1回の実行で2回聞かれる
SELECT &&col FROM employees ORDER BY &col;   -- 1回だけ聞かれる（&&で定義済み）
SELECT * FROM employees WHERE last_name = '&name';   -- King と入力 → 'King'
```

## 3-12 DEFINE / UNDEFINE / SET VERIFY { #define }

<div class="rule-box" markdown>

**判定基準**

| コマンド | 働き |
|---|---|
| `DEFINE 変数 = 値` | 変数に値を設定（以後 `&変数` で入力を求められない） |
| `DEFINE` | 定義済み変数の一覧 |
| `UNDEFINE 変数` | 定義を削除（`&&` の保持値も消える） |
| `SET VERIFY ON` | 置換 **前（old）と後（new）** のSQLを表示 |
| `SET VERIFY OFF` | 置換前後の表示をしない |
| `SET DEFINE OFF` | `&` を置換変数として扱わない（`&` を文字として使える） |
| `ACCEPT 変数 PROMPT '文'` | プロンプトを指定して入力を受ける |

- これらは **SQL*Plusコマンド**。**SQL Developer でも使える**（スクリプト実行）

</div>

```text
SQL> SET VERIFY ON
SQL> SELECT last_name FROM employees WHERE employee_id = &id;
Enter value for id: 100
old   1: SELECT last_name FROM employees WHERE employee_id = &id
new   1: SELECT last_name FROM employees WHERE employee_id = 100
```

| 選択肢の言い回し（SET VERIFY ON） | 判定 |
|---|---|
| SQL*Plusで使用できる | ✅ |
| 置換変数を含むSQLの実行時に、置換前後のSQLが表示される | ✅ |
| SQL Developerでは使用できない | ❌ |
| `&&` の値をリセットするか確認が表示される | ❌（そのような機能はない。リセットは UNDEFINE） |

## ○×クイック判定 { #quiz }

| 記述 | 判定 | ひとこと |
|---|---|---|
| `WHERE col = NULL` は構文エラーになる | ❌ | 実行できるが0行 |
| `WHERE col NOT IS NULL` は実行できる | ❌ | IS NOT NULL |
| LIKEの `_` は0文字以上 | ❌ | ちょうど1文字（0文字以上は `%`） |
| LIKEで `?` は任意の1文字を表す | ❌ | `_` |
| `NOT IN` のリストにNULLがあると0行 | ✅ | |
| `BETWEEN 6000 AND 4000` はエラー | ❌ | 0行 |
| BETWEENは両端を含む | ✅ | |
| ANDはORより先に評価される | ✅ | NOT → AND → OR |
| ORDER BYの既定は降順 | ❌ | 昇順 |
| ORDER BYにはSELECTリストにない列を指定できない | ❌ | 指定できる（DISTINCT等を除く） |
| 昇順ではNULLは最初に並ぶ | ❌ | 最後 |
| `&` の変数は一度入力すればセッション中保持される | ❌ | それは `&&` |
| `&&` の変数はUNDEFINEするまで再入力を求められない | ✅ | |
| SET VERIFY ONで置換前後のSQLが表示される | ✅ | |
| SET VERIFYはSQL Developerでは使えない | ❌ | 使える |
