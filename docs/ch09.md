# 第9章 集合演算

!!! abstract "この章で問われる形"
    - 「次の文を実行すると **何行** 返されますか」（または「構文エラーになる」）
    - 「UNIONとUNION ALLについて正しい記述はどれですか」
    - 「INTERSECTによる複合問合せについて正しい記述はどれですか」
    - 「表Aにあって表Bにないデータを抽出したい。どの問合せですか」
    - 「複合問合せの列数・データ型・列名・ORDER BYについて正しい記述はどれですか」

---

## 9-1 集合演算子の種類 { #operators }

<div class="rule-box" markdown>

**判定基準**

| 演算子 | 結果 | 重複 | ソート |
|---|---|---|---|
| `UNION` | 和集合（どちらかにある行） | **除く** | される |
| `UNION ALL` | 和集合 | **残す** | **されない** |
| `INTERSECT` | 積集合（**両方にある** 行） | 除く | される |
| `MINUS` | 差集合（**1つ目にあって2つ目にない** 行） | 除く | される |

- `UNION`・`UNION ALL`・`INTERSECT` は **順番を入れ替えても結果の行は同じ**
- **`MINUS` は順番を入れ替えると結果が変わる**

</div>

### 「Aにあって、Bにない」を選ぶ

```sql
SELECT * FROM customer_a MINUS SELECT * FROM customer_b;      -- ✅ Aにあって Bにない
SELECT * FROM customer_b MINUS SELECT * FROM customer_a;      -- ⚠️ 逆（Bにあって Aにない）
SELECT * FROM customer_a INTERSECT SELECT * FROM customer_b;  -- ⚠️ 両方にある
SELECT * FROM customer_a UNION SELECT * FROM customer_b;      -- ⚠️ どちらかにある
```

| 選択肢の言い回し | 判定 |
|---|---|
| UNION ALL を UNION に置き換えると行数が増える可能性がある | ❌（減るか同じ） |
| UNION では出力はソートされる | ✅ |
| UNION ALL では重複行は排除される | ❌ |
| UNION は各問合せに共通するデータを返す | ❌（それはINTERSECT） |
| INTERSECT は1つ目にあって2つ目にない行を返す | ❌（それはMINUS） |
| INTERSECT は問合せの順番を入れ替えても結果は変わらない | ✅ |

## 9-2 列数とデータ型の一致 { #rules }

<div class="rule-box" markdown>

**判定基準**

1. 各SELECTの **列数が同じ** であること（違えば ORA-01789）
2. 対応する列の **データ型グループが同じ** であること（数値と文字などは ORA-01790）
   - 型の **長さ・精度** は違ってよい（`VARCHAR2(10)` と `VARCHAR2(50)` など）
   - **`NULL` はどの型の列にも対応できる**
3. 列数を合わせたいときは `NULL` や `TO_CHAR(NULL)`、ダミーのリテラルで埋める

</div>

```sql
SELECT employee_id, last_name FROM employees
UNION
SELECT department_id, department_name FROM departments;    -- ✅ 数値・文字が対応

SELECT employee_id, last_name FROM employees
UNION
SELECT department_name, department_id FROM departments;    -- ❌ 型の並びが逆

SELECT employee_id, last_name FROM employees
UNION
SELECT department_id FROM departments;                     -- ❌ 列数が違う

SELECT employee_id, last_name FROM employees
UNION
SELECT department_id, NULL FROM departments;               -- ✅ NULLで埋める
```

## 9-3 列名 { #column-names }

<div class="rule-box" markdown>

**判定基準**

1. 各SELECTの **列名は違ってよい**
2. 結果の列見出しは **最初のSELECT** の列名（列別名）になる
3. 2つ目以降のSELECTの列別名は **無視される**（書いてもエラーにはならない）

</div>

---

## 9-4 ORDER BY { #order-by }

<div class="rule-box" markdown>

**判定基準**

1. `ORDER BY` は **文全体の最後に1回だけ** 書ける
2. 途中のSELECTに ORDER BY を書くと **エラー**（最後の1つだけ有効、ではない）
3. ORDER BYで使えるのは
   - **最初のSELECTの** 列名・列別名
   - **列の位置番号**
4. 2つ目以降のSELECTだけにある列名・別名では指定できない

</div>

```sql
SELECT employee_id id, last_name FROM employees
UNION
SELECT department_id, department_name FROM departments
ORDER BY id;                 -- ✅ 最初のSELECTの別名

ORDER BY 2;                  -- ✅ 位置
ORDER BY last_name;          -- ✅ 最初のSELECTの列名
ORDER BY department_name;    -- ❌ 2つ目のSELECTの列名

SELECT employee_id, last_name FROM employees ORDER BY last_name
UNION
SELECT department_id, department_name FROM departments;   -- ❌ 途中にORDER BY
```

| 選択肢の言い回し | 判定 |
|---|---|
| ORDER BYでは最後の問合せの列名や別名で指定する | ❌（最初） |
| ORDER BYのソート列は必ず列の位置で指定する | ❌（名前でも可） |
| 列名・別名で指定する場合、最初の問合せの列名・別名のみ認識される | ✅ |
| 各問合せに独自のORDER BYを書いてもエラーにならず、最後のものだけ有効 | ❌ |

## 9-5 重複排除・ソート・NULL { #sort-dup }

<div class="rule-box" markdown>

**判定基準**

1. UNION・INTERSECT・MINUS は、**全列の組合せ** で重複を判定する
2. **集合演算の重複判定では NULL と NULL は等しい** とみなす（WHERE句の比較とは違う）
   → NULLを含む行も無視されずに比較される
3. ソートは最初の列から昇順（UNION ALL はソートしない）

</div>

```sql
SELECT 'A', NULL FROM dual
UNION
SELECT 'A', NULL FROM dual;        -- 1行（NULLどうしは重複とみなす）

SELECT 'A', 1 FROM dual
INTERSECT
SELECT 'A', NULL FROM dual;        -- 0行（1 と NULL は違う）
```

!!! warning "ひっかけ"
    「集合演算では選択列に含まれるNULLは無視される」→ ❌
    NULLも値の1つとして比較され、NULLどうしは同じとみなされます。

## 9-6 優先順位 { #precedence }

<div class="rule-box" markdown>

**判定基準**

1. 集合演算子どうしの優先順位は **すべて同じ**
2. **上から（左から）順に** 評価する
3. 順序を変えたいときは **かっこ** を使う

</div>

```sql
A UNION B INTERSECT C          -- (A UNION B) INTERSECT C
A UNION (B INTERSECT C)        -- B INTERSECT C が先
```

## 9-7 行数の数え方 { #count-rows }

<div class="rule-box" markdown>

**判定手順**

1. まず **構文チェック**：列数、対応する列のデータ型グループ、ORDER BYの位置
   → 違反があれば「構文エラー」
2. 各SELECTの **結果の行を実際の値で書き出す**
   - 関数・式は評価してから比べる（`UPPER('a')` → `'A'`、`ROUND(100)` → `100`、`101-1` → `100`）
   - **`SYSDATE` は1つの文の中では同じ値**（各SELECTで同じ）
   - 列別名は比較に関係ない
3. **上から順に** 演算子を適用する
   - UNION / INTERSECT / MINUS → 重複を除く
   - UNION ALL → 重複も残す

</div>

### 例1

```sql
SELECT 'Y' AS c1, SYSDATE - 1 AS c2, 50 AS c3 FROM dual
UNION
SELECT UPPER('y'), SYSDATE - 1, ROUND(50.2) FROM dual
UNION ALL
SELECT INITCAP('y'), SYSDATE - 1, 49 + 1 FROM dual;
```

| 段階 | 行 | 行数 |
|---|---|---|
| 1つ目 | ('Y', 昨日, 50) | |
| 2つ目 | ('Y', 昨日, 50) → 1つ目と同じ | |
| 1 UNION 2 | 重複を除いて1行 | **1** |
| 3つ目 | ('Y', 昨日, 50) | |
| （結果）UNION ALL 3 | 重複も残す | **2** |

### 例2

```sql
SELECT 'K' c1, SYSDATE c2, 1 c3 FROM dual
INTERSECT
SELECT LOWER('K'), SYSDATE, 1 FROM dual;
```

`LOWER('K')` は `'k'`。`'K'` と `'k'` は違う値なので共通行がなく **0行**。

!!! tip "選択肢に「構文エラー」があったら"
    まず列数と型を確認。`NULL` は何型にも合う、型の長さが違うのは問題ない、の2点を思い出してから判断します。
