# 第14章 ユーザー・権限・ロール

!!! abstract "この章で問われる形"
    - 「**構文エラーにならずに正常に実行される**コマンドはどれですか」（GRANT）
    - 「**システム権限でのみ** 実行できる操作はどれですか」「**オブジェクト権限が必要** な操作はどれですか」
    - 「表を作成しデータを入れ索引を作るユーザーに **必要なもの** はどれですか」
    - 「オブジェクト権限の付与に関して正しい記述はどれですか」
    - 「権限とロールに関して正しい記述はどれですか」

---

## 14-1 ユーザーとスキーマ { #user }

<div class="rule-box" markdown>

**判定基準**

```sql
CREATE USER ユーザー名 IDENTIFIED BY パスワード
  [DEFAULT TABLESPACE 表領域]
  [QUOTA { n M | UNLIMITED } ON 表領域];
```

1. ユーザーを作ると、同じ名前の **スキーマ**（そのユーザーが所有するオブジェクトの集まり）ができる
2. ログインには **`CREATE SESSION`** システム権限が必要
3. 表を作ってデータを入れるには **`CREATE TABLE`** 権限 ＋ **表領域の割当て（QUOTA）** が必要
4. 自分のパスワードの変更（`ALTER USER 自分 IDENTIFIED BY ...`）に権限は不要
5. 他人のスキーマのオブジェクトは `スキーマ名.オブジェクト名` で参照する（権限があれば）

</div>

---

## 14-2 システム権限とオブジェクト権限 { #sys-obj-priv }

<div class="rule-box" markdown>

**判定基準**

| | システム権限 | オブジェクト権限 |
|---|---|---|
| 対象 | **データベース全体**／ある種類の操作 | **特定のオブジェクト**（hr.employees など） |
| 例 | `CREATE SESSION`、`CREATE TABLE`、`CREATE VIEW`、`CREATE SEQUENCE`、`CREATE SYNONYM`、`CREATE PUBLIC SYNONYM`、`CREATE PROCEDURE`、`UNLIMITED TABLESPACE`、**`〜 ANY 〜`**（`SELECT ANY TABLE`、`DROP ANY TABLE`、`EXECUTE ANY PROCEDURE`…） | `SELECT`、`INSERT`、`UPDATE`、`DELETE`、`ALTER`、`INDEX`、`REFERENCES`、`EXECUTE`、`READ`、`WRITE` |
| 再付与のオプション | `WITH ADMIN OPTION` | `WITH GRANT OPTION` |

**オブジェクトの種類ごとに付与できるオブジェクト権限**

| 権限 | 表 | ビュー | シーケンス | プロシージャ／ファンクション | ディレクトリ |
|---|---|---|---|---|---|
| SELECT | ✅ | ✅ | ✅ | | |
| INSERT / UPDATE / DELETE | ✅ | ✅ | | | |
| ALTER | ✅ | | ✅ | | |
| INDEX | ✅ | | | | |
| REFERENCES | ✅ | ✅ | | | |
| EXECUTE | | | | ✅ | |
| READ | ✅（12c以降） | ✅（12c以降） | | | ✅ |
| WRITE | | | | | ✅ |

</div>

```sql
GRANT ALTER ON hr.emp_seq TO scott;           -- ✅ シーケンスにALTER
GRANT REFERENCES ON hr.emp_seq TO scott;      -- ❌ シーケンスにREFERENCESはない
GRANT EXECUTE ON hr.calc_bonus TO scott;      -- ✅ プロシージャにEXECUTE
GRANT INDEX ON hr.emp_view TO scott;          -- ❌ ビューにINDEXはない
```

## 14-3 GRANT構文の判定 { #grant-syntax }

<div class="rule-box" markdown>

**判定基準**

```sql
-- システム権限・ロール
GRANT 権限 [, 権限...] TO 付与先 [, 付与先...] [WITH ADMIN OPTION];

-- オブジェクト権限
GRANT 権限 [(列...)] [, 権限...] ON [スキーマ.]オブジェクト TO 付与先 [, ...] [WITH GRANT OPTION];
```

1. **システム権限とオブジェクト権限を1つのGRANTに混在させられない**（ON の有無で形が違う）
2. **`WITH GRANT OPTION` の付与先にロールは指定できない**（ユーザーと PUBLIC は可）
3. `WITH ADMIN OPTION` の付与先はユーザー・ロールのどちらでも可
4. 付与先は **カンマ区切りで複数**（ユーザーとロールの混在も可）
5. オブジェクト権限には `ON` が必須。システム権限には `ON` を付けない
6. `ALL [PRIVILEGES]` でそのオブジェクトの全権限を付与できる

</div>

| SQL | 判定 | 理由 |
|---|---|---|
| `GRANT SELECT ON hr.employees TO scott WITH GRANT OPTION;` | ✅ | |
| `GRANT UPDATE ON hr.employees TO PUBLIC WITH GRANT OPTION;` | ✅ | PUBLICへのGRANT OPTIONは可 |
| `GRANT SELECT ON hr.employees TO mgr_role WITH GRANT OPTION;` | ❌ | **ロールにGRANT OPTION不可** |
| `GRANT CREATE TABLE, CREATE VIEW TO mgr_role, scott WITH ADMIN OPTION;` | ✅ | ロール・ユーザー混在可 |
| `GRANT CREATE VIEW, SELECT ON hr.employees TO scott;` | ❌ | **システム権限とオブジェクト権限の混在** |
| `GRANT CREATE TABLE ON hr TO scott;` | ❌ | システム権限に ON は付けない |
| `GRANT SELECT TO scott;` | ❌ | ON がないとシステム権限として解釈され、「SELECT」というシステム権限は存在しない |
| `GRANT CREATE SESSION TO scott WITH GRANT OPTION;` | ❌ | システム権限は ADMIN OPTION |

## 14-4 列レベルのオブジェクト権限 { #column-priv }

<div class="rule-box" markdown>

**判定基準**

1. 列を指定して付与できるのは **INSERT・UPDATE・REFERENCES だけ**
2. **SELECT は列を指定できない**（列を絞りたいならビューを作って付与）
3. 表だけでなく **ビュー** に対しても列を指定できる（INSERT・UPDATE・REFERENCES）

</div>

```sql
GRANT UPDATE (salary, commission_pct) ON hr.employees TO scott;   -- ✅
GRANT SELECT (last_name) ON hr.employees TO scott;                -- ❌
```

| 選択肢の言い回し | 判定 |
|---|---|
| UPDATE権限を付与するとき、表またはビューの列を指定できる | ✅ |
| SELECT権限を付与するとき、表またはビューの列を指定できる | ❌ |
| REFERENCESは、シーケンスに対して付与できる | ❌ |
| EXECUTEは、プロシージャに対して付与できる | ✅ |

---

## 14-5 権限の取消しと連鎖 { #revoke }

<div class="rule-box" markdown>

**判定基準**

```sql
REVOKE システム権限 FROM 対象;
REVOKE オブジェクト権限 ON オブジェクト FROM 対象 [CASCADE CONSTRAINTS];
```

| | ADMIN OPTION 付きの **システム権限** | GRANT OPTION 付きの **オブジェクト権限** |
|---|---|---|
| A から取り消したとき、A が他人に付与した分は | **残る（連鎖しない）** | **連鎖して取り消される** |
| 取り消せる人 | ADMIN OPTION を持つ **誰でも**（付与した本人でなくてよい） | **付与した本人**（など） |

- `GRANT OPTION` だけを取り消すことはできない（権限ごと取り消して付け直す）
- `REFERENCES` を取り消すときに、それを使った外部キー制約があれば `CASCADE CONSTRAINTS` が必要

</div>

!!! example "連鎖の例"
    - DBA → A に `CREATE TABLE ... WITH ADMIN OPTION`、A → B に `CREATE TABLE`
      → A から取り消しても **B は CREATE TABLE を持ったまま**
    - hr → A に `SELECT ON hr.employees WITH GRANT OPTION`、A → B に `SELECT ON hr.employees`
      → A から取り消すと **B の権限も取り消される**

## 14-6 オブジェクト権限を付与できる人 { #who-can-grant }

<div class="rule-box" markdown>

**判定基準**

1. **オブジェクトの所有者**（所有者は自分のオブジェクトに対する **すべての権限** を最初から持つ）
2. その権限を **WITH GRANT OPTION 付き** で付与されたユーザー（さらに GRANT OPTION 付きで他人に付与できる）
3. `GRANT ANY OBJECT PRIVILEGE` システム権限を持つユーザー

→ 「データベース管理者だけが付与できる」は ❌

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| オブジェクト権限を付与できるのはデータベース管理者のみ | ❌ |
| 表の所有者はデフォルトでその表の SELECT と INSERT 権限のみを持つ | ❌（すべて持つ） |
| GRANT OPTION付きで付与されたユーザーは、GRANT OPTION付きで別のユーザーに付与できる | ✅ |
| オブジェクト権限をロールに付与することはできない | ❌（できる。GRANT OPTIONが付けられないだけ） |

---

## 14-7 権限が不要な操作 { #no-priv }

<div class="rule-box" markdown>

**判定基準：自分のスキーマで完結する操作の多くは権限不要**

| 操作 | 権限 |
|---|---|
| 自分の表を問い合わせる・DMLする | **不要** |
| 自分の表に索引を作る（自分のスキーマ内） | **不要**（表領域の割当ては必要） |
| 自分のオブジェクトを変更・削除する | **不要** |
| 自分のプロシージャを実行する | **不要** |
| 自分の表の権限を他人に付与する | **不要** |
| 自分のパスワードを変更する | **不要** |

ただし **新しく作成する** ときは CREATE系システム権限が必要（`CREATE TABLE`、`CREATE VIEW`、`CREATE PROCEDURE`…）

</div>

---

## 14-8 どの権限が必要か（判定フロー） { #need-which }

<div class="rule-box" markdown>

**判定手順**

1. **自分のスキーマ** のオブジェクトに対する操作か？
   - 作成 → **システム権限**（CREATE ○○）
   - それ以外（参照・変更・削除・索引作成）→ **不要**
2. **他人の特定のオブジェクト** を使う操作か？ → **オブジェクト権限**
   - 他人の表を参照 → `SELECT`
   - 他人の表を参照する **外部キー** を自分の表に作る → `REFERENCES`
   - 他人の表に（自分のスキーマで）**索引を作る** → `INDEX`
   - 他人のプロシージャを実行 → `EXECUTE`
   - **ディレクトリオブジェクト** にアクセス → `READ` / `WRITE`
3. **任意のスキーマ／データベース全体** に対する操作か？（「任意の」「他のスキーマの○○を削除」）
   → **システム権限（`〜 ANY 〜`）**
   - データベース内の任意のファンクションを実行 → `EXECUTE ANY PROCEDURE`
   - 他のスキーマのシーケンスを削除 → `DROP ANY SEQUENCE`（シーケンスにDROPのオブジェクト権限はない）

</div>

| 操作 | 必要なもの | 種類 |
|---|---|---|
| データベース内の任意のファンクションを実行 | EXECUTE ANY PROCEDURE | システム権限 |
| 他のスキーマのシーケンスを削除 | DROP ANY SEQUENCE | システム権限 |
| 自分のスキーマの表を問い合わせる | なし | — |
| 自分のスキーマのプロシージャを実行 | なし | — |
| 既存のディレクトリオブジェクトにアクセス | READ / WRITE ON DIRECTORY | オブジェクト権限 |
| 別のスキーマの表に索引を作成 | INDEX ON 表 | オブジェクト権限 |
| 別のスキーマの表を参照する外部キーを追加 | REFERENCES ON 表 | オブジェクト権限 |
| 自分のスキーマの表の SELECT 権限を他人に付与 | なし | — |
| 自分のスキーマにプロシージャを作成 | CREATE PROCEDURE | システム権限 |
| 自分の表に索引を作成 | なし（QUOTAは必要） | — |

!!! example "「表を作り、データを入れ、索引を作る」ユーザーに必要なもの"
    - **CREATE TABLE** システム権限
    - 表を格納する **表領域の割当て（QUOTA）**
    - （ログインのための CREATE SESSION）
    - `CREATE ANY TABLE` は他人のスキーマ用なので不要。自分の表への索引に `INDEX` 権限も不要

## 14-9 ロール { #role }

<div class="rule-box" markdown>

**判定基準**

```sql
CREATE ROLE ロール名 [IDENTIFIED BY パスワード];
GRANT 権限 TO ロール名;               -- ロールに権限を入れる
GRANT ロール名 TO ユーザー | ロール | PUBLIC;
REVOKE ロール名 FROM ユーザー;
DROP ROLE ロール名;
```

1. ロールは **権限をまとめたもの**。**どのスキーマにも属さない**（所有者はいない）
2. ロールには **システム権限・オブジェクト権限・他のロール** を付与できる（循環は不可）
3. ロールは **ユーザー・他のロール・PUBLIC** に付与できる
4. オブジェクト権限をロールに付与するとき **WITH GRANT OPTION は付けられない**
5. ロールを削除すると、そのロールを付与されていた全ユーザーから権限がなくなる
6. ロールに追加した権限は、そのロールを持つユーザーに **すぐに** 反映される
7. ロール経由の権限では、**他人の表を使うビューやプロシージャは作れない**（直接付与が必要）
8. 定義済みロール：`CONNECT`（CREATE SESSION）、`RESOURCE`（CREATE TABLE・SEQUENCE・PROCEDURE…）、`DBA`

</div>

---

## 14-10 PUBLIC { #public }

<div class="rule-box" markdown>

**判定基準**

1. `PUBLIC` は **全ユーザー**（今後作られるユーザーも含む）を表す
2. PUBLIC に付与した権限は全員が使える
3. **PUBLIC に付与した権限を、特定のユーザーだけ REVOKE して除外することはできない**
   （そのユーザーには直接付与していないのでエラー。除外したいなら、対象ユーザーに個別に付与するかロールを使う）

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| 特定ユーザーを除く全員に付与したいなら、PUBLICに付与してから特定ユーザーからREVOKEする | ❌ |
| すべてのロールの所有者は SYSTEM である | ❌（ロールに所有者はいない） |
| ロールに対して別のロールを付与することはできない | ❌ |
| ロールを PUBLIC に対して付与することができる | ✅ |
