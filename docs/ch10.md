# 第10章 DMLとトランザクション

!!! abstract "この章で問われる形"
    - 「次の文について正しい記述はどれですか」（SET句の副問合せ、複数列の更新）
    - 「マルチテーブル・インサートに関して正しい記述はどれですか」「INSERT ALLをINSERT FIRSTに変えても結果は変わりませんか」
    - 「MERGE文に関して正しい記述はどれですか」
    - 「未コミットのトランザクションが **コミットされる** のはどのような場合ですか」
    - 「次の一連の文を実行しました。**実行後の状況** について正しい記述はどれですか」

---

## 10-1 INSERT { #insert }

<div class="rule-box" markdown>

**判定基準**

1. `INSERT INTO 表 [(列, ...)] VALUES (値, ...)`
2. 列リストを省略したら、**表のすべての列に定義順で** 値を指定する
3. **列の数と値の数は一致**（多い：ORA-00913、少ない：ORA-00947）
4. 列リストに書かなかった列は **DEFAULT値、なければNULL**
   → その列が **NOT NULL（DEFAULTなし）なら ORA-01400**
5. 値の位置に `DEFAULT` キーワード、`NULL` を書ける
6. 副問合せで挿入：`INSERT INTO 表 [(列...)] SELECT ...`（**VALUES は書かない**）
7. 1つのVALUES句で挿入できるのは1行（19c）

</div>

```sql
INSERT INTO dept (dept_id, name) VALUES (10, 'Sales');           -- ✅
INSERT INTO dept VALUES (20, 'HR', DEFAULT);                     -- ✅ 全列（3列の表）
INSERT INTO dept (dept_id, name) VALUES (30);                    -- ❌ 値が足りない
INSERT INTO dept (dept_id) VALUES (40);                          -- ⚠️ name が NOT NULL（DEFAULTなし）ならエラー
INSERT INTO dept_hist SELECT * FROM dept WHERE dept_id > 10;    -- ✅ 副問合せ
INSERT INTO dept_hist VALUES (SELECT * FROM dept);               -- ❌ VALUES と副問合せの組合せ
```

## 10-2 UPDATE { #update }

<div class="rule-box" markdown>

**判定基準**

1. `UPDATE 表 SET 列 = 値 [, 列 = 値 ...] [WHERE ...]`
2. **1つのUPDATEで複数列を更新できる**
3. **WHEREを省略すると全行** が更新される
4. **SET句に副問合せを書ける**
   - `SET 列 = (副問合せ)` … 1行1列
   - `SET (列1, 列2) = (SELECT 列a, 列b ...)` … **1行**で、列数が一致
5. SET句の副問合せが **0行ならNULL** で更新、**2行以上ならエラー**（ORA-01427）
6. `SET 列 = DEFAULT` も可

</div>

```sql
-- 社員202の職種・給与を、社員201と同じにする
UPDATE employees
SET (job_id, salary) = (SELECT job_id, salary FROM employees WHERE employee_id = 201)
WHERE employee_id = 202;     -- ✅ 202 が更新され、201 と同じ値になる
```

| 選択肢の言い回し（上の文） | 判定 |
|---|---|
| SET句に副問合せを書けないのでエラー | ❌ |
| 1つのUPDATEで複数の列を更新できないのでエラー | ❌ |
| 社員202の列が更新され、社員201と同じ値になる | ✅ |
| 社員201の列が更新され、社員202と同じ値になる | ❌（更新されるのはWHEREの行） |

!!! tip "どちらが更新されるか"
    **外側のWHERE** が更新対象、**副問合せのWHERE** は値の取得元です。

## 10-3 DELETE { #delete }

<div class="rule-box" markdown>

**判定基準**

1. `DELETE [FROM] 表 [WHERE ...]` … **FROM は省略できる**
2. WHEREを省略すると **全行削除**（ロールバック可能。TRUNCATEとの違い）
3. 子表から参照されている親表の行は削除できない（ORA-02292）
   → 外部キーに `ON DELETE CASCADE` / `ON DELETE SET NULL` があれば削除できる

</div>

DELETEとTRUNCATEの比較は → [12章 DROPとTRUNCATE](ch12.md#drop-truncate)
副問合せを使う削除は → [8章 DMLでの副問合せ](ch08.md#dml-subquery)

## 10-4 マルチテーブルINSERT { #multi-insert }

<div class="rule-box" markdown>

**判定基準：構文**

```sql
INSERT { ALL | FIRST }
  WHEN 条件1 THEN INTO 表1 [(列...)] [VALUES (...)]
  WHEN 条件2 THEN INTO 表2 ...
  [ELSE INTO 表3 ...]
SELECT ... ;                 -- 元になる副問合せ（必須）
```

| 種類 | 動き |
|---|---|
| 無条件 `INSERT ALL INTO ... INTO ...` | 副問合せの各行を **すべてのINTO** に挿入 |
| 条件付き `INSERT ALL WHEN ...` | **すべてのWHENを評価** し、真になった **すべての表** に挿入（複数の表に入りうる） |
| 条件付き `INSERT FIRST WHEN ...` | 上から評価し、**最初に真になったWHENだけ** に挿入 |
| `ELSE` | **どのWHENも真にならなかった行** を挿入 |

**判定基準：制限**

1. 挿入先は **表のみ**。**ビューは指定できない**（マテリアライズドビュー・リモート表も不可）
2. 副問合せでは **シーケンスを使えない**
3. 副問合せの対象にビューを使うのはOK

</div>

### 例：ALL と FIRST の違い

`sales` 表：(1, 120)、(2, 70)、(3, 10) を次の条件で振り分ける

```sql
INSERT ALL
  WHEN amount >= 100 THEN INTO big
  WHEN amount >= 50  THEN INTO mid
  ELSE INTO small
SELECT * FROM sales;
```

| 行 | `INSERT ALL` | `INSERT FIRST` に変えると |
|---|---|---|
| 120 | big **と** mid | big のみ |
| 70 | mid | mid |
| 10 | small | small |

- `ALL` → `FIRST` にすると **結果が変わる**（120の行）
- `ELSE` を `WHEN 1=1 THEN` に変えると、ALLでは **全行が small にも入る** ので結果が変わる
- 金額10の行は、どの表にも入らないのではなく **ELSE の表に入る**

## 10-5 MERGE { #merge }

<div class="rule-box" markdown>

**判定基準**

```sql
MERGE INTO 対象表 t
USING ソース s              -- 表・ビュー・副問合せ
ON (t.id = s.id)            -- 必須・かっこ必須
WHEN MATCHED THEN
  UPDATE SET t.col = s.col [WHERE ...] [DELETE WHERE ...]
WHEN NOT MATCHED THEN
  INSERT (t.id, t.col) VALUES (s.id, s.col) [WHERE ...];
```

1. 対象表（INTO）は **1つだけ**
2. `USING` には **表・ビュー・副問合せ** を指定できる
3. **`ON` 句は省略できない**
4. `WHEN MATCHED` → **UPDATE**（とDELETE）、`WHEN NOT MATCHED` → **INSERT**。逆は不可
5. どちらかの WHEN 句は省略できる
6. **ON句で使った列は UPDATE できない**（ORA-38104）
7. DMLなので **ロールバックできる**

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| USING句に副問合せを指定できる | ✅ |
| ON句は省略可能である | ❌ |
| WHEN MATCHED句にINSERTを指定できる | ❌ |
| INTO句に複数のターゲット表を指定すると、複数の表をまとめて更新できる | ❌ |
| ON句で指定した列をUPDATEで更新できる | ❌ |

## 10-6 トランザクションの開始と終了 { #tx-boundary }

<div class="rule-box" markdown>

**判定基準：開始**

- 前のトランザクションが終わった後の **最初のDML** で自動的に始まる
  （ROLLBACK後にDMLを実行すれば、新しいトランザクションが自動で始まる）

**判定基準：終了**

| きっかけ | 未コミットの変更 |
|---|---|
| `COMMIT` | **コミット** |
| **DDL**（CREATE / ALTER / DROP / **TRUNCATE** / RENAME / COMMENT）を実行 | **コミット**（変更と関係ない表へのDDLでも） |
| **DCL**（GRANT / REVOKE）を実行 | **コミット** |
| SQL*Plus を **正常終了**（EXIT / QUIT）・正常に切断 | **コミット** |
| `ROLLBACK` | **ロールバック** |
| クライアントの **異常終了**・セッションの強制終了・ネットワーク障害 | **ロールバック** |
| インスタンス障害・`SHUTDOWN IMMEDIATE` / `ABORT` | **ロールバック** |
| **他のセッション** の COMMIT / ROLLBACK | **影響しない** |

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| SQL*Plusを正常に終了すると、未コミットはロールバックされる | ❌（コミット） |
| クライアント・プロセスが異常終了するとロールバックされる | ✅ |
| TRUNCATE文を発行すると、未コミットはロールバックされる | ❌（DDLなのでコミット） |
| ROLLBACK後にDMLを発行すると、新しいトランザクションが自動的に開始される | ✅ |
| 同じユーザーの別セッションでCOMMITすると、こちらもコミットされる | ❌ |
| DBAがSHUTDOWN IMMEDIATEを発行するとコミットされる | ❌（ロールバック） |
| 関係のない表をTRUNCATEするとコミットされる | ✅ |

!!! note "文レベルのロールバック"
    トランザクションの途中で1つの文がエラーになっても、取り消されるのは **その文だけ**。
    それまでのDMLは残り、トランザクションは続きます。

## 10-7 SAVEPOINT { #savepoint }

<div class="rule-box" markdown>

**判定基準**

1. `SAVEPOINT 名前` でトランザクションの途中に目印を付ける
2. `ROLLBACK TO [SAVEPOINT] 名前`
   - そのセーブポイント **より後** の変更だけを取り消す
   - **それより後に作ったセーブポイントは消える**（指定したセーブポイント自体は残る）
   - **トランザクションは終わらない**（続けてDMLできる）
3. `ROLLBACK`（TOなし）は **トランザクション全体** を取り消し、セーブポイントもすべて消える
4. `COMMIT`（または暗黙コミット）で **セーブポイントはすべて消える**
5. 同じ名前のセーブポイントを作ると、**後のものに置き換わる**
6. 存在しないセーブポイントへの ROLLBACK TO はエラー

</div>

### 実行後の状態を追う手順

1. **DDLがあれば、そこで確定** として区切る
2. 各文の後の「表の中身」と「有効なセーブポイント」を書き出す
3. ROLLBACK TO のたびに、そのセーブポイントの時点の中身に戻す

```sql
INSERT INTO t VALUES (1);
SAVEPOINT a;
INSERT INTO t VALUES (2);
SAVEPOINT b;
DELETE FROM t WHERE id = 1;
ROLLBACK TO b;              -- DELETEだけ取消し → {1, 2}
INSERT INTO t VALUES (3);   -- {1, 2, 3}
ROLLBACK TO a;              -- a以降を取消し → {1}、bは消える
INSERT INTO t VALUES (4);   -- {1, 4}
COMMIT;                     -- 確定：2行（1 と 4）
```

```sql
INSERT INTO t VALUES (1);
SAVEPOINT a;
INSERT INTO t VALUES (2);
CREATE TABLE x (c NUMBER);  -- 暗黙コミット：{1, 2} 確定、セーブポイントaは消える
INSERT INTO t VALUES (3);
ROLLBACK TO a;              -- ❌ エラー（aはもうない）。3 は未コミットのまま残る
ROLLBACK;                   -- 3 を取消し → {1, 2}
```

## 10-8 読取り一貫性とロック { #read-consistency }

<div class="rule-box" markdown>

**判定基準**

1. コミット前の変更は **自分のセッションでだけ見える**。他のセッションは変更前の値を見る
2. 問合せは **開始時点でコミット済みのデータ** を一貫して返す（文レベルの読取り一貫性）
3. 変更前のデータは **UNDO** に保存され、ロールバックと読取り一貫性に使われる
4. DMLは対象 **行をロック** する。他のセッションが同じ行を変更しようとすると **待たされる**
5. 読む側と書く側は互いに待たない（SELECTはロックを待たない）
6. ロックはコミット／ロールバックで解放される

</div>

---

## 10-9 SELECT ... FOR UPDATE { #for-update }

<div class="rule-box" markdown>

**判定基準**

1. 問合せた行を **事前にロック** する（トランザクションが始まる）
2. `NOWAIT` … ロックされていたら待たずにエラー。`WAIT n` … n秒待つ
3. `FOR UPDATE OF 列` … 結合時、その列を持つ表の行だけロック
4. ロックは **COMMIT / ROLLBACK で解放**
5. DISTINCT・GROUP BY・集計関数・集合演算とは併用できない

</div>

```sql
SELECT * FROM employees WHERE department_id = 10 FOR UPDATE NOWAIT;
```
