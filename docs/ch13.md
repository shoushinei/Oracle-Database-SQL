# 第13章 ビュー

!!! abstract "この章で問われる形"
    - 「ビューについて正しい記述はどれですか」
    - 「ビューに対してDMLを実行できないのはどのような場合ですか」
    - 「WITH CHECK OPTION について正しい記述はどれですか」

---

## 13-1 ビューの作成 { #create-view }

<div class="rule-box" markdown>

**判定基準**

```sql
CREATE [OR REPLACE] [FORCE | NOFORCE] VIEW ビュー名 [(列別名, ...)]
AS 副問合せ
[WITH CHECK OPTION [CONSTRAINT 名前]]
[WITH READ ONLY [CONSTRAINT 名前]];
```

1. ビューは **SELECT文に名前を付けて保存したもの**。データ（セグメント）は持たない
2. 作成には `CREATE VIEW` システム権限（他人の表を使うなら、その表の権限が **ロール経由ではなく直接** 必要）
3. **`OR REPLACE`** … 既存のビューを置き換える。**付与済みのオブジェクト権限はそのまま残る**（付与し直す必要はない）
4. **`FORCE`** … 実表が **存在しなくても** ビューを作成できる（無効な状態で作られる）。既定は NOFORCE
5. 副問合せの **式には列別名が必要**（またはビュー名の後に列別名リスト）
6. 副問合せに **ORDER BY を書ける**
7. 副問合せに結合・GROUP BY・副問合せ・集合演算を使ってよい

</div>

```sql
CREATE VIEW emp_v AS
  SELECT employee_id, last_name, salary*12 FROM employees;           -- ❌ 式に別名がない

CREATE VIEW emp_v AS
  SELECT employee_id, last_name, salary*12 annual FROM employees;    -- ✅

CREATE VIEW emp_v (id, name, annual) AS
  SELECT employee_id, last_name, salary*12 FROM employees;           -- ✅ 列別名リスト

CREATE FORCE VIEW future_v AS SELECT * FROM not_yet_created;         -- ✅ 無効なビューとして作成
```

## 13-2 ビューの変更・削除 { #alter-drop-view }

<div class="rule-box" markdown>

**判定基準**

1. **`ALTER VIEW` では定義（副問合せ）を変更できない**
   → 再コンパイル（`ALTER VIEW v COMPILE`）や制約の操作だけ
2. 定義を変えるには **`CREATE OR REPLACE VIEW`**
3. `DROP VIEW ビュー名` で削除。**実表とそのデータには影響しない**
4. 実表を削除するとビューは **無効** になる（自動削除されない）
5. **ビューに索引は作成できない**

</div>

## 13-3 ビューに対するDML { #view-dml }

<div class="rule-box" markdown>

**判定基準：ビューの副問合せに次のどれかがあると、DMLできない**

| 含まれるもの | DELETE | UPDATE | INSERT |
|---|---|---|---|
| **集計関数**（SUM、COUNT など） | ❌ | ❌ | ❌ |
| **GROUP BY / HAVING** | ❌ | ❌ | ❌ |
| **DISTINCT** | ❌ | ❌ | ❌ |
| **ROWNUM** 疑似列 | ❌ | ❌ | ❌ |
| **集合演算子**（UNIONなど） | ❌ | ❌ | ❌ |
| **式で定義された列**（`salary*12` など） | ✅ | その列は ❌ | その列は ❌ |
| 実表の **NOT NULL列（DEFAULTなし）がビューに含まれない** | ✅ | ✅ | ❌ |
| `WITH READ ONLY` | ❌ | ❌ | ❌ |

- 単純なビュー（1つの表・関数なし・グループ化なし）は、基本的にDMLできる
- 結合ビューでは、**キー保存表**（結合しても主キーが一意のままの表）の列だけ変更できる
- DMLできないビューでも、**INSTEAD OF トリガー** を作ればDMLを受け付けられる

</div>

---

## 13-4 WITH CHECK OPTION / WITH READ ONLY { #check-option }

<div class="rule-box" markdown>

**判定基準**

1. **`WITH CHECK OPTION`** … ビュー経由の INSERT・UPDATE で、**ビューの WHERE 条件から外れる行** を作れなくする
   - 条件を満たすDMLは **実行できる**（DMLを全部禁止するわけではない）
   - DELETEは制限しない（そもそもビューで見える行しか消せない）
2. **`WITH READ ONLY`** … ビュー経由の **すべてのDML** を禁止する

</div>

```sql
CREATE VIEW dept50_v AS
  SELECT employee_id, last_name, department_id
  FROM employees WHERE department_id = 50
WITH CHECK OPTION;

UPDATE dept50_v SET last_name = 'Smith' WHERE employee_id = 120;   -- ✅ 部門50のまま
UPDATE dept50_v SET department_id = 80 WHERE employee_id = 120;    -- ❌ ビューから外れる（ORA-01402）
INSERT INTO dept50_v VALUES (999, 'New', 50);                       -- ✅（他の列の制約を満たせば）
INSERT INTO dept50_v VALUES (998, 'New', 80);                       -- ❌
```

## ○×クイック判定 { #quiz }

| 記述 | 判定 | ひとこと |
|---|---|---|
| CREATE OR REPLACE VIEW で定義を変えたら、SELECT権限を付与し直す必要がある | ❌ | 権限は残る |
| 存在しない表に対してビューを定義することは絶対にできない | ❌ | FORCE |
| WITH CHECK OPTION を使うとビュー経由のDMLはすべて禁止される | ❌ | 条件外の行を作るDMLだけ |
| WITH READ ONLY を使うとビュー経由のDMLはすべて禁止される | ✅ | |
| ALTER VIEW でビューの定義問合せを置き換えることはできない | ✅ | CREATE OR REPLACE |
| ビュー経由で索引を作成すると実表に索引が作成される | ❌ | ビューに索引は作れない |
| ビューを削除すると実表のデータも削除される | ❌ | |
| ビューの副問合せにORDER BYを書ける | ✅ | |
| GROUP BYを含むビューにはINSERTできない | ✅ | |
| DISTINCTを含むビューの行は削除できる | ❌ | |
| ビューはデータを格納するセグメントを持つ | ❌ | |
