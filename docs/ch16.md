# 第16章 タイムゾーンと期間

!!! abstract "この章で問われる形"
    - 「DBTIMEZONE と SESSIONTIMEZONE が○○のとき、CURRENT_TIMESTAMP で **戻る値** はどれですか」
    - 「データ型について正しい記述はどれですか」（TIMESTAMP系・INTERVAL系）
    - 「次の期間リテラルのうち正しいものはどれですか」

---

## 16-1 日時データ型 { #datetime-types }

<div class="rule-box" markdown>

**判定基準**

| 型 | 小数秒 | タイムゾーン | 格納のされ方 |
|---|---|---|---|
| `DATE` | ❌ | ❌ | 年月日時分秒 |
| `TIMESTAMP[(n)]` | ✅（n=0〜9、既定6） | ❌ | 年月日時分秒＋小数秒 |
| `TIMESTAMP[(n)] WITH TIME ZONE` | ✅ | ✅ **格納する** | 値と一緒にタイムゾーン（オフセットまたは地域名）を保存 |
| `TIMESTAMP[(n)] WITH LOCAL TIME ZONE` | ✅ | ❌ 格納しない | **データベースのタイムゾーンに変換して格納**、取り出すときに **セッションのタイムゾーンで表示** |

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| TIMESTAMP 型は秒まで格納できるが、小数秒は格納できない | ❌（それはDATE） |
| TIMESTAMP WITH LOCAL TIME ZONE の列は、セッションのタイムゾーンのまま格納される | ❌（DBのタイムゾーンに正規化） |
| TIMESTAMP WITH TIME ZONE はタイムゾーン情報も格納する | ✅ |
| DATE 型は小数秒を格納できる | ❌ |

## 16-2 データベースとセッションのタイムゾーン { #tz-session }

<div class="rule-box" markdown>

**判定基準**

| | 意味 | 確認 | 変更 |
|---|---|---|---|
| `DBTIMEZONE` | **データベース** のタイムゾーン | `SELECT DBTIMEZONE FROM dual;` | `ALTER DATABASE SET TIME_ZONE = ...` |
| `SESSIONTIMEZONE` | **セッション** のタイムゾーン（既定はクライアントの設定） | `SELECT SESSIONTIMEZONE FROM dual;` | `ALTER SESSION SET TIME_ZONE = ...` |

タイムゾーンの書き方：`'+09:00'`（オフセット）、`'Asia/Tokyo'`（地域名）、`LOCAL`、`DBTIMEZONE`

</div>

---

## 16-3 現在日時を返す関数 { #tz-functions }

<div class="rule-box" markdown>

**判定基準**

| 関数 | 戻り値の型 | どこの時刻か | 表示に使う書式パラメータ |
|---|---|---|---|
| `SYSDATE` | DATE | **DBサーバーのOS** | NLS_DATE_FORMAT |
| `SYSTIMESTAMP` | TIMESTAMP WITH TIME ZONE | **DBサーバーのOS** | NLS_TIMESTAMP_TZ_FORMAT |
| `CURRENT_DATE` | DATE | **セッションのタイムゾーン** | NLS_DATE_FORMAT |
| `CURRENT_TIMESTAMP` | TIMESTAMP WITH TIME ZONE | **セッションのタイムゾーン** | NLS_TIMESTAMP_TZ_FORMAT |
| `LOCALTIMESTAMP` | TIMESTAMP | **セッションのタイムゾーン** | NLS_TIMESTAMP_FORMAT |

覚え方：**`SYS` で始まる → サーバー**、**`CURRENT_`／`LOCAL` → セッション**

</div>

### 「CURRENT_TIMESTAMP で戻る値」の判定手順

1. **どのタイムゾーンの時刻か** → セッションのタイムゾーン（SESSIONTIMEZONE）
2. **どの書式で表示されるか** → `NLS_TIMESTAMP_TZ_FORMAT`（日付だけ・時刻なしにはならない）
3. 書式に `TZR` があれば **地域名**、`TZH:TZM` なら **オフセット** が付く

!!! example "例"
    - DBTIMEZONE＝`Asia/Tokyo`、SESSIONTIMEZONE＝`America/New_York`（冬時間：UTC−5）
    - 東京で 1月15日 09:00 のとき、NLS_TIMESTAMP_TZ_FORMAT が `DD-MON-RR HH:MI:SS.FF AM TZR`

    | 候補 | 判定 | 理由 |
    |---|---|---|
    | 15-JAN-24 09:00:00.xxxxxx AM Asia/Tokyo | ❌ | DBのタイムゾーンの時刻（SYSTIMESTAMPならこちらに近い） |
    | 14-JAN-24 07:00:00.xxxxxx PM America/New_York | ✅ | セッションのタイムゾーン、TZ書式で表示 |
    | 14-JAN-24 | ❌ | 日付だけ（DATE型をNLS_DATE_FORMATで表示した形） |

## 16-4 期間データ型（INTERVAL） { #interval-types }

<div class="rule-box" markdown>

**判定基準**

| 型 | 格納するもの | 精度の既定 |
|---|---|---|
| `INTERVAL YEAR[(年の精度)] TO MONTH` | **年と月** の期間（例：6年4か月） | 年の精度 2（0〜9） |
| `INTERVAL DAY[(日の精度)] TO SECOND[(小数秒の精度)]` | **日・時・分・秒** の期間（例：3日5時間） | 日の精度 2、小数秒 6 |

- INTERVAL DAY TO SECOND は **24時間を超える期間も格納できる**（日の部分で表す）
- 年月の期間と日時の期間は **別の型**（互いに足せない）

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| INTERVAL DAY TO SECOND は24時間を超える時間間隔は格納できない | ❌ |
| INTERVAL YEAR TO MONTH は「6年4か月」のような期間を格納できる | ✅ |
| INTERVAL YEAR TO MONTH で「3日」を格納できる | ❌（日はDAY TO SECOND） |

---

## 16-5 期間リテラル { #interval-literal }

<div class="rule-box" markdown>

**判定基準**

1. 形は `INTERVAL '値' 先頭フィールド[(精度)] [TO 末尾フィールド]`
2. **先頭フィールドの桁数が精度（既定2）を超えるとエラー**（ORA-01873）→ `(3)` などで精度を指定
3. 末尾側のフィールドは通常の範囲内（月 0〜11、時 0〜23、分・秒 0〜59）

</div>

```sql
INTERVAL '6-4' YEAR TO MONTH         -- ✅ 6年4か月
INTERVAL '18' MONTH                  -- ✅ 1年6か月
INTERVAL '120' YEAR                  -- ❌ 3桁（既定精度2）
INTERVAL '120' YEAR(3)               -- ✅
INTERVAL '4 05:30:00' DAY TO SECOND  -- ✅ 4日5時間30分
INTERVAL '100' DAY                   -- ❌ 3桁
INTERVAL '100' DAY(3)                -- ✅
INTERVAL '36' HOUR                   -- ✅ 36時間（先頭フィールドなので24超OK）
INTERVAL '2 25' DAY TO HOUR          -- ❌ 末尾の時が24以上
```

### 変換関数

| 関数 | 例 |
|---|---|
| `TO_YMINTERVAL('年-月')` | `TO_YMINTERVAL('01-06')` → 1年6か月 |
| `TO_DSINTERVAL('日 時:分:秒')` | `TO_DSINTERVAL('2 12:00:00')` → 2日12時間 |
| `NUMTOYMINTERVAL(n, 'YEAR' / 'MONTH')` | `NUMTOYMINTERVAL(18, 'MONTH')` |
| `NUMTODSINTERVAL(n, 'DAY' / 'HOUR' / 'MINUTE' / 'SECOND')` | `NUMTODSINTERVAL(90, 'MINUTE')` |

## 16-6 期間を使った加減算 { #interval-arith }

<div class="rule-box" markdown>

**判定基準**

| 式 | 結果 |
|---|---|
| 日付／TIMESTAMP ± INTERVAL | 日付／TIMESTAMP |
| TIMESTAMP − TIMESTAMP | **INTERVAL DAY TO SECOND** |
| DATE − DATE | **数値**（日数） |
| INTERVAL ± INTERVAL（同じ種類） | INTERVAL |
| INTERVAL YEAR TO MONTH ± INTERVAL DAY TO SECOND | ❌ |
| INTERVAL × 数値 | INTERVAL |

- 月の期間を足した結果が **存在しない日付** になるとエラー
  （`DATE '2024-01-31' + INTERVAL '1' MONTH` → 2月31日は存在しない → ❌ ORA-01839）
  → `ADD_MONTHS` は月末に調整してくれる（2024-02-29）

</div>

```sql
SELECT hire_date + INTERVAL '3' MONTH FROM employees;            -- ✅
SELECT SYSTIMESTAMP + INTERVAL '1 12:00:00' DAY TO SECOND FROM dual;  -- ✅ 1日半後
SELECT TIMESTAMP '2024-01-02 00:00:00' - TIMESTAMP '2024-01-01 06:00:00' FROM dual;
  -- ✅ 0日18時間（INTERVAL DAY TO SECOND 型で返る）
```

### その他の関数

| 関数 | 働き |
|---|---|
| `EXTRACT(YEAR FROM d)` / `EXTRACT(HOUR FROM ts)` | 年・月・日・時・分・秒、タイムゾーン要素を取り出す（DATEからHOURは取り出せない） |
| `FROM_TZ(timestamp, 'タイムゾーン')` | TIMESTAMPにタイムゾーンを付けて TIMESTAMP WITH TIME ZONE にする |
| `ts AT TIME ZONE 'Asia/Tokyo'` | 指定したタイムゾーンの時刻に変換する |
| `TZ_OFFSET('Asia/Tokyo')` | オフセット（`'+09:00'`）を文字列で返す |
| `TO_TIMESTAMP` / `TO_TIMESTAMP_TZ` | 文字列を TIMESTAMP／TIMESTAMP WITH TIME ZONE に変換 |
