## 11-1 索引の基本 { #index-basics }

<div class="rule-box" markdown>

**判定基準**

1. `CREATE [UNIQUE | BITMAP] INDEX 索引名 ON 表 (列 [, 列...])`
2. 複数列（複合索引）・式（ファンクションベース索引）にも作れる
3. 索引は **スキーマオブジェクト**。**表と別のスキーマに作ることもできる**（CREATE ANY INDEX があれば）
4. 索引は **DMLのたびに自動で更新** される（手動で再構築する必要はない）
5. 表を削除すると、その表の索引も削除される
6. **ビューには索引を作れない**

</div>

```sql
CREATE INDEX emp_name_ix ON employees (last_name);                   -- ✅
CREATE UNIQUE INDEX emp_mail_ux ON employees (email);                -- ✅
CREATE INDEX emp_upper_ix ON employees (UPPER(last_name));           -- ✅ ファンクションベース
CREATE INDEX emp_dept_ix ON employees (department_id, job_id);       -- ✅ 複合索引
CREATE INDEX v_ix ON emp_view (last_name);                           -- ❌ ビューには不可
```

## 11-2 索引が自動で作られる場合 { #index-auto }

<div class="rule-box" markdown>

**判定基準**

| 制約 | 索引の自動作成 |
|---|---|
| **PRIMARY KEY** | ✅ 一意索引が作られる |
| **UNIQUE** | ✅ 一意索引が作られる |
| **FOREIGN KEY** | ❌ **作られない** |
| CHECK / NOT NULL | ❌ |

- その列に **既存の索引** があれば、新しく作らずに **既存の索引を使う**（非一意索引でも主キーに使える）
- 制約を削除・無効化すると、自動作成された索引も削除される（既存の索引を流用していた場合は残る）

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| PRIMARY KEY・UNIQUE・FOREIGN KEY制約を定義した列には自動的に索引が作成される | ❌（FKは作られない） |
| 非一意索引を持つ列に主キー制約を追加するには、先に索引を削除する必要がある | ❌（流用できる） |

---

## 11-3 索引の維持・変更・削除 { #index-maintain }

<div class="rule-box" markdown>

**判定基準**

1. 索引の内容は DML で **自動的に** 反映される
2. **一意索引を非一意索引に変更することはできない**（削除して作り直す）
3. `DROP INDEX 索引名` で削除。表のデータには影響しない
4. **制約が使っている索引は DROP INDEX できない**（ORA-02429。制約を削除・無効化する）
5. `DROP TABLE` で表がごみ箱に移ると、索引も **一緒にごみ箱に移る**（UNUSABLEになるのではない）
6. 同じ列の組合せに **同じ種類の索引** は2つ作れない（種類・一意性などが違えば作れる。ただし可視は1つ）

</div>

---

## 11-4 UNUSABLE と INVISIBLE { #unusable-invisible }

<div class="rule-box" markdown>

**判定基準**

| | UNUSABLE（使用不可） | INVISIBLE（不可視） |
|---|---|---|
| 設定 | `ALTER INDEX ix UNUSABLE` | `ALTER INDEX ix INVISIBLE` |
| オプティマイザが使うか | 使わない | **使わない** |
| DMLで更新されるか | **更新されない** | **更新される** |
| 元に戻す | `ALTER INDEX ix REBUILD` | `ALTER INDEX ix VISIBLE` |

- `ALTER TABLE ... MOVE` すると、その表の索引は UNUSABLE になる（オプション指定がない場合）

</div>

## 11-5 索引が使われにくい条件 { #index-usage }

| WHERE句 | 索引（last_name列の通常の索引） |
|---|---|
| `last_name = 'King'` | 使える |
| `last_name LIKE 'Ki%'` | 使える（前方一致） |
| `last_name LIKE '%ng'` | 使いにくい（後方一致） |
| `UPPER(last_name) = 'KING'` | 使えない（関数をかけている。ファンクションベース索引なら可） |
| `last_name IS NULL` | 使えない（単一列のB-tree索引はNULLを格納しない） |

## 11-6 シーケンスの定義 { #sequence-create }

<div class="rule-box" markdown>

**判定基準**

```sql
CREATE SEQUENCE シーケンス名
  [INCREMENT BY n]        -- 増分（既定 1。負なら減少）
  [START WITH n]          -- 最初の値（既定は昇順なら MINVALUE）
  [MAXVALUE n | NOMAXVALUE]
  [MINVALUE n | NOMINVALUE]   -- 昇順の既定は 1
  [CYCLE | NOCYCLE]       -- 既定 NOCYCLE
  [CACHE n | NOCACHE];    -- 既定 CACHE 20
```

1. **NOCYCLE** で最大値に達すると、次のNEXTVALは **エラー**
2. **CYCLE** で最大値に達すると、**MINVALUE に戻る**（START WITH に戻るのではない）
3. **CACHE n** … n個の値を **メモリに事前割当て** して高速に発番する（障害時には欠番になる）
4. シーケンスは **特定の表に属さない**（複数の表で共有できる）

</div>

### 定義の読み方

```sql
CREATE SEQUENCE ord_seq
  INCREMENT BY 5
  START WITH 1000
  MAXVALUE 99999
  NOCYCLE
  CACHE 50;
```

| 選択肢の言い回し | 判定 |
|---|---|
| 1000から始まり、5ずつ増える | ✅ |
| 5から始まり、1000ずつ増える | ❌（逆） |
| 新しい値を発番するには CURRVAL を参照する | ❌（NEXTVAL） |
| 最大値に達すると1000に戻る | ❌（NOCYCLEなのでエラー。CYCLEでも戻るのはMINVALUE） |
| 値がキャッシュされ、効率よく発番される | ✅ |

## 11-7 NEXTVAL と CURRVAL { #nextval-currval }

<div class="rule-box" markdown>

**判定基準**

1. `シーケンス名.NEXTVAL` … **次の値を発番** する
2. `シーケンス名.CURRVAL` … **そのセッションで最後に発番した値** を返す
3. セッションで **一度もNEXTVALを実行していない** のにCURRVALを参照するとエラー（ORA-08002）
4. **1つの文の中で NEXTVAL を何回書いても、1行あたり1回だけ増える**（同じ値になる）
5. 他のセッションが発番しても、自分のCURRVALは変わらない

</div>

---

## 11-8 NEXTVAL / CURRVAL を使える場所 { #nextval-where }

<div class="rule-box" markdown>

**判定基準**

| 使える ✅ | 使えない ❌ |
|---|---|
| 副問合せでない **SELECTリスト** | `DISTINCT` を含むSELECT |
| `INSERT` の **VALUES** | `GROUP BY` / `HAVING` / `ORDER BY` を含むSELECT |
| `INSERT ... SELECT` の **SELECTリスト** | **集合演算**（UNIONなど）を含むSELECT |
| `UPDATE` の **SET** | SELECT・UPDATE・DELETEの **副問合せ** の中 |
| 列の **DEFAULT**（12c以降） | **ビュー** の定義問合せ |
| | **CHECK制約** |
| | マルチテーブルINSERTの副問合せ |

</div>

```sql
INSERT INTO orders (id, item) VALUES (ord_seq.NEXTVAL, 'pen');    -- ✅
SELECT ord_seq.NEXTVAL FROM dual;                                  -- ✅
UPDATE orders SET id = ord_seq.NEXTVAL WHERE id IS NULL;           -- ✅
SELECT DISTINCT ord_seq.NEXTVAL FROM dual;                         -- ❌
SELECT ord_seq.NEXTVAL FROM dual UNION SELECT 1 FROM dual;         -- ❌
```

## 11-9 欠番が出る場合 { #sequence-gap }

<div class="rule-box" markdown>

**判定基準：シーケンスの値が連続しない理由**

1. **ロールバック** しても、発番した値は戻らない
2. **インスタンス障害** などでキャッシュの値が失われる
3. **同じシーケンスを複数の表** で使っている

→ 「シーケンスを使えば必ず連番になる」は ❌

</div>

---

## 11-10 ALTER SEQUENCE / DROP SEQUENCE { #alter-sequence }

<div class="rule-box" markdown>

**判定基準**

1. INCREMENT BY・MAXVALUE・MINVALUE・CYCLE・CACHE は変更できる
2. **START WITH は変更できない**（作り直す）
3. MAXVALUE を **現在値より小さく** はできない
4. 変更は **以降の発番** にだけ影響する
5. `DROP SEQUENCE 名前` で削除。使っていた表のデータには影響しない

</div>

---

## 11-11 IDENTITY列 { #identity }

<div class="rule-box" markdown>

**判定基準**

```sql
id NUMBER GENERATED ALWAYS AS IDENTITY            -- 値の指定は不可（常に自動）
id NUMBER GENERATED BY DEFAULT AS IDENTITY        -- 省略時に自動。値の指定も可
id NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY -- NULLを指定しても自動採番
```

1. 内部的にシーケンスが自動作成される
2. `ALWAYS` の列に値を明示してINSERT／UPDATEするとエラー

</div>

## 11-12 シノニム { #synonym }

<div class="rule-box" markdown>

**判定基準：作成と権限**

```sql
CREATE [OR REPLACE] [PUBLIC] SYNONYM シノニム名 FOR [スキーマ.]オブジェクト;
DROP [PUBLIC] SYNONYM シノニム名;
```

| 操作 | 必要なシステム権限 |
|---|---|
| 自分のスキーマにプライベートシノニム作成 | `CREATE SYNONYM` |
| 他のスキーマにシノニム作成 | `CREATE ANY SYNONYM` |
| パブリックシノニム作成 | **`CREATE PUBLIC SYNONYM`** |
| パブリックシノニム削除 | `DROP PUBLIC SYNONYM` |

**判定基準：性質**

1. 対象：**表・ビュー・シーケンス・プロシージャ・ファンクション・パッケージ・別のシノニム** など
2. 目的：**スキーマ名を書かずに** アクセスする、長い名前を短くする、実体の場所を隠す
3. シノニムは **定義だけ**（**セグメントを持たない**、データを持たない）
4. **プライベートシノニムは、同じスキーマ内の他のオブジェクトと同じ名前にできない**（同じ名前空間）
5. パブリックシノニムは、スキーマのオブジェクトと同じ名前でもよい
6. 参照先が削除されても **シノニムは自動削除されない**（無効になるだけ）
7. 存在しないオブジェクトに対しても作成できる
8. シノニムを使っても、**参照先へのアクセス権限は別途必要**
9. 名前の解決順：**自分のスキーマのオブジェクト → パブリックシノニム**

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| プライベートシノニムには、同じスキーマの他のオブジェクトと同じ名前を付けられる | ❌ |
| シーケンスやビュー、別のシノニムに対してシノニムを作成できる | ✅ |
| プライベートシノニムはセグメントを持つ | ❌ |
| スキーマ名を指定せずに表にアクセスするためにシノニムを使うことがある | ✅ |
| 参照しているオブジェクトが削除されると、シノニムも自動的に削除される | ❌ |
| PUBLICシノニムを作成するには CREATE PUBLIC SYNONYM システム権限が必要 | ✅ |
