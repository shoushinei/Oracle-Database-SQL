## 1-1 SQLの特徴 { #sql-features }

<div class="rule-box" markdown>

**判定基準**

1. SQLは **リレーショナルデータベース** を操作する言語（階層型・ネットワーク型向けではない）
2. SQLは **非手続き型（宣言型）**：「**何が欲しいか**」だけを書き、「**どうやって探すか**（アクセス方法・検索手順）」は書かない
   → 検索方法は **オプティマイザ** が決める
3. 表どうしの結合は **列の値（結合条件）** で行う。ROWIDなどの物理的な位置を指定する必要はない
4. 物理的な格納方法を変えても、SQL（論理構造）は変えなくてよい（**物理データ独立性**）

</div>

| 選択肢の言い回し | 判定 | 理由 |
|---|---|---|
| SQLは階層型／ネットワーク型データベースに適した言語 | ❌ | リレーショナル型の言語 |
| 結合するには各表のROWIDを指定する必要がある | ❌ | 値で結合する。ROWIDは不要 |
| データを論理的に処理でき、検索方法を指定する必要はない | ✅ | 非手続き型 |
| SQLでは処理手順（ループ等）を記述して検索する | ❌ | 手順を書くのはPL/SQLなど手続き型 |

### SQL文の分類

| 分類 | 文 | ポイント |
|---|---|---|
| 問合せ | `SELECT` | |
| DML（データ操作） | `INSERT` `UPDATE` `DELETE` `MERGE` | ロールバック可能 |
| DDL（データ定義） | `CREATE` `ALTER` `DROP` `RENAME` `TRUNCATE` `COMMENT` | **暗黙コミット**、ロールバック不可 |
| DCL（データ制御） | `GRANT` `REVOKE` | 暗黙コミット |
| トランザクション制御 | `COMMIT` `ROLLBACK` `SAVEPOINT` | |

!!! warning "ひっかけ"
    `TRUNCATE` は「行を消す」ので DML に見えますが **DDL** です。→ [12章 DROPとTRUNCATE](ch12.md#drop-truncate)

## 1-2 E-Rモデルとリレーションシップ { #er-model }

<div class="rule-box" markdown>

**判定基準**

1. 「**AはBを複数持てる**」かつ「**BはAを複数持てる**」→ **多対多（M:N）**
2. 片方向だけ複数 → **1対多（1:N）**。両方とも1つ → **1対1**
3. 多対多はリレーショナル表として **そのままは実装できない**
   → **交差表（関連表・中間表）** を作り、**2つの1対多に分解** する
4. 交差表は、両方の表の主キーを **外部キー** として持つ（その組合せが交差表の主キーになることが多い）

</div>

```text
例: 「学生は複数の講座を受講でき、講座は複数の学生が受講する」

STUDENTS  1 ──< ENROLLMENTS >── 1  COURSES
(学生)          (交差表:受講)          (講座)
                student_id (FK)
                course_id  (FK)
```

### 読み方のコツ

- ビジネスルールの文章を **両方向** から読む
  - 「1人の学生は → 講座を **何件** 取れる？」
  - 「1つの講座は → 学生を **何人** 持てる？」
- 両方「複数」なら多対多。選択肢では「**交差表を作成して1対多に分解する必要がある**」が正しい形

| 選択肢の言い回し（多対多のルールに対して） | 判定 |
|---|---|
| AとBの間に1対多の関連が成り立っている | ❌（片方向しか見ていない） |
| 多対多の関連を分解せず、そのまま表として実装する必要がある | ❌ |
| 交差表を作成して1対多に分解する必要がある | ✅ |

### E-R図の用語

| 用語 | 意味 |
|---|---|
| エンティティ | 管理対象（表になる） |
| 属性 | エンティティの性質（列になる） |
| リレーションシップ | エンティティ間の関連（外部キーになる） |
| 一意識別子（UID） | 行を一意に特定する属性（主キーになる） |
| オプショナリティ | 関連が「必須」か「任意」か（任意なら外部キーにNULLを許す） |

## 1-3 キーとNULL { #keys }

<div class="rule-box" markdown>

**判定基準**

| キー | NULL | 重複 | 1表にいくつ |
|---|---|---|---|
| **主キー（PRIMARY KEY）** | **不可** | 不可 | **1つだけ**（複数列の複合キーは可） |
| **一意キー（UNIQUE）** | **可（複数行でも可）** | 不可（NULL以外） | 複数可 |
| **外部キー（FOREIGN KEY）** | **可** | 可 | 複数可 |

</div>

- 外部キーは、親表の **主キーまたは一意キー** を参照する
- 外部キーの値は「親表に存在する値」か「NULL」のどちらか
- 一意キーにNULLが **何行でも** 入るのは、NULLどうしは「等しい」と判定されないから

!!! warning "ひっかけ"
    - 「一意キー列にNULLは **1行だけ** 挿入できる」→ ❌（何行でも可）
    - 「外部キー列にNULLは入力できない」→ ❌（入力可。NOT NULL制約を付けた場合のみ不可）
    - 「主キーは1列でなければならない」→ ❌（複合主キー可。ただし主キー **制約** は1表に1つ）

制約の構文的なルールは → [12章 制約](ch12.md#constraint-syntax)

## 1-4 SQL*Plus と SQL Developer { #tools }

<div class="rule-box" markdown>

**判定基準**

1. **SQL*Plus**：コマンドライン（文字ベース）のツール
2. **SQL Developer**：GUIツール。SQL*Plusのコマンドの多く（`DESCRIBE`、`SET VERIFY` など）を **スクリプトとして実行可能**
3. SQL文は `;`（または `/`）で実行。**SQL*Plusコマンド** は `;` 不要で、1行で完結する
4. SQL*Plusコマンドは **省略形** が使える（`DESCRIBE` → `DESC`）

</div>

| 種類 | 例 | 終端 | データベースに送られるか |
|---|---|---|---|
| SQL文 | `SELECT` `INSERT` `CREATE` ... | `;` または `/` | 送られる |
| SQL*Plusコマンド | `DESCRIBE` `SET` `DEFINE` `UNDEFINE` `SHOW` `CONNECT` `EXIT` | 不要 | クライアント側で処理 |

!!! warning "ひっかけ"
    「DESCRIBEはSQL*Plusでのみ使える（SQL Developerでは使えない）」→ ❌
    「SET VERIFY はSQL Developerでは使えない」→ ❌
    いずれもSQL Developerでも使えます。→ [2章 DESCRIBE](ch02.md#describe) / [3章 VERIFY](ch03.md#define)

## 1-5 初期化パラメータと ALTER SESSION { #alter-session }

<div class="rule-box" markdown>

**判定基準**

1. `ALTER SESSION SET パラメータ = 値` は **そのセッションだけ** に有効（他のセッションや次回接続には影響しない）
2. 日付の表示・解釈に関わるのは `NLS_DATE_FORMAT`、`NLS_DATE_LANGUAGE`、`NLS_LANGUAGE`、`NLS_TERRITORY` など
3. `ALTER SESSION` は **DDLではない**（トランザクションを暗黙コミットしない）

</div>

```sql
ALTER SESSION SET NLS_DATE_FORMAT = 'YYYY-MM-DD HH24:MI:SS';   -- ✅
ALTER SESSION SET NLS_DATE_LANGUAGE = 'AMERICAN';              -- ✅ 月名が JAN, FEB...
ALTER SESSION SET TIME_ZONE = 'Asia/Tokyo';                    -- ✅ セッションのタイムゾーン
```

!!! tip "問題文の前提条件として出てくる"
    「NLS_DATE_FORMATが DD-MON-RR に設定されている」などの前提は、**暗黙の変換が成功するか** の判定に使います。→ [5章 暗黙の変換](ch05.md#implicit)
