# 第7章 結合

!!! abstract "この章で問われる形"
    - 「次の問合せを実行すると、**何行** のデータが返されますか」（クロス結合・外部結合）
    - 「**正常に実行される**問合せはどれですか」（USING・NATURAL JOIN の表接頭辞、表別名）
    - 「Oracle結合構文／ANSI結合構文について正しい記述はどれですか」
    - 「内部結合と外部結合について正しい説明はどれですか」
    - 「自己結合／非等価結合について正しい記述はどれですか」

---

## 7-1 結合の種類と返る行数 { #join-types }

<div class="rule-box" markdown>

**判定基準**

| 結合 | 返る行 |
|---|---|
| **内部結合** | 結合条件に **一致する行だけ** |
| **左外部結合** | 内部結合の結果 ＋ **左表** の一致しない行（右側の列はNULL） |
| **右外部結合** | 内部結合の結果 ＋ **右表** の一致しない行（左側の列はNULL） |
| **完全外部結合** | 内部結合の結果 ＋ 左右 **両方** の一致しない行 |
| **クロス結合（デカルト積）** | **左の行数 × 右の行数** |

- 外部結合は「一致する行 **も** 返す」。一致しない行 **だけ** を返すわけではない
- したがって行数は **内部結合 ≦ 外部結合**

</div>

### 行数の計算例

`EMP` 4行（部門10が2人、20が2人）、`DEPT` 3行（10、20、30）

| 結合 | 行数 | 理由 |
|---|---|---|
| `EMP CROSS JOIN DEPT` | **12** | 4 × 3 |
| `EMP JOIN DEPT ON 部門一致` | 4 | 全員が一致 |
| `EMP RIGHT JOIN DEPT ON 部門一致` | 5 | 4 ＋ 社員のいない部門30 |
| `EMP LEFT JOIN DEPT ON 部門一致` | 4 | 全員が一致するので増えない |

| 選択肢の言い回し | 判定 |
|---|---|
| 外部結合は結合条件が一致しない行のみを戻す | ❌ |
| 完全外部結合は結合条件が一致しない行のみを戻す | ❌ |
| 内部結合で返される行数は外部結合より常に多い | ❌ |
| 内部結合は結合条件が一致する行のみを戻す | ✅ |

## 7-2 結合構文の一覧 { #join-syntax }

<div class="rule-box" markdown>

**判定基準：2つの構文系統**

| | ANSI（SQL:1999準拠） | Oracle独自構文 |
|---|---|---|
| 書き方 | `FROM a JOIN b ON ...` | `FROM a, b WHERE ...` |
| 内部結合 | `[INNER] JOIN ... ON / USING`、`NATURAL JOIN` | `WHERE a.x = b.x` |
| 外部結合 | `LEFT / RIGHT / FULL [OUTER] JOIN` | `WHERE a.x = b.x(+)` |
| **完全外部結合** | ✅ `FULL OUTER JOIN` | ❌ **構文がない**（両側に(+)は不可） |
| クロス結合 | `CROSS JOIN` | `FROM a, b`（結合条件なし） |
| 3つ以上の表 | ✅ | ✅ |
| 非等価結合 | ✅（`ON` に任意の条件） | ✅ |

</div>

| 選択肢の言い回し | 判定 |
|---|---|
| Oracle結合構文には完全外部結合の構文がある | ❌ |
| ANSI結合構文ではデカルト積を生成できる | ✅（CROSS JOIN） |
| ANSI結合構文では3つ以上の表を結合できない | ❌ |
| ANSI結合構文には自然結合の構文がある | ✅（NATURAL JOIN） |

## 7-3 ON句 { #on }

<div class="rule-box" markdown>

**判定基準**

1. `ON` には **任意の条件** を書ける（等価・非等価・複数条件の AND/OR）
2. 結合する列の **名前が違ってもよい**
3. 両方の表にある同名の列は **表名か表別名で修飾が必要**（修飾しないと ORA-00918 列のあいまいな定義）
4. 結合後の絞り込みは `WHERE`（内部結合なら `ON` に `AND` で書いても同じ結果）

</div>

```sql
SELECT e.last_name, d.department_name
FROM employees e JOIN departments d
  ON e.department_id = d.department_id
WHERE e.salary > 10000;                       -- ✅

SELECT e.last_name, d.department_name
FROM employees e JOIN departments d
  ON e.department_id = d.department_id AND e.salary > 10000;   -- ✅ 内部結合なら同じ結果
```

!!! warning "外部結合では ON と WHERE で結果が変わる"
    `LEFT JOIN ... ON 条件 AND d.location_id = 1700` … 一致しない左表の行も残る
    `LEFT JOIN ... ON 条件 WHERE d.location_id = 1700` … 結合後に絞るので、NULLになった行は消える

## 7-4 USING句 { #using }

<div class="rule-box" markdown>

**判定基準**

1. `JOIN 表 USING (列名)` … **両方の表に同じ名前で存在する列** を指定する（かっこ必須）
2. **USINGで指定した列には、問合せのどこでも表名・表別名を付けられない**（ORA-25154）
   - SELECTリスト、WHERE、ORDER BY のすべてで修飾不可
3. USINGに指定しない他の同名列は、修飾が必要
4. USING と NATURAL を同時には使えない。USING と ON も同時には使えない

</div>

```sql
SELECT department_id, d.department_name
FROM employees e JOIN departments d USING (department_id);            -- ✅

SELECT e.department_id, d.department_name
FROM employees e JOIN departments d USING (department_id);            -- ❌ USING列に修飾子

SELECT department_id FROM employees e JOIN departments d USING (department_id)
WHERE d.department_id = 10;                                           -- ❌ WHEREでも修飾不可

SELECT last_name FROM employees JOIN departments USING department_id; -- ❌ かっこがない

SELECT last_name, manager_id
FROM employees e JOIN departments d USING (department_id);            -- ❌ manager_idは両表にありあいまい
```

---

## 7-5 NATURAL JOIN { #natural }

<div class="rule-box" markdown>

**判定基準**

1. **両方の表で同じ名前のすべての列** を自動的に等価結合する
2. 共通列には **表名・表別名を付けられない**（ORA-25155）
3. `ON` や `USING` を **一緒に書けない**
4. 同名列のデータ型が互換でないとエラー
5. 同名列がなければ **クロス結合** になる
6. 意図しない列（例：両表の `manager_id`）まで結合条件になる点に注意

</div>

```sql
SELECT department_id, department_name FROM employees NATURAL JOIN departments;      -- ✅
SELECT d.department_id FROM employees e NATURAL JOIN departments d;                 -- ❌ 共通列に修飾子
SELECT * FROM employees NATURAL JOIN departments USING (department_id);             -- ❌ USINGと併用
```

!!! tip "HRスキーマの例"
    `employees` と `departments` には `department_id` と `manager_id` の両方があるため、
    NATURAL JOIN は **2列とも一致** する行だけを返します（部門長と上司が同じ社員だけ）。

## 7-6 表接頭辞と表別名 { #prefix }

<div class="rule-box" markdown>

**判定基準**

1. 複数の表に同名の列があれば、**修飾しないとエラー**（ORA-00918）。片方にしかない列は修飾不要
2. FROMで **表別名を付けたら、その文の中では表別名を使う**（元の表名で修飾すると ORA-00904）
3. 表別名に `AS` は付けられない（列別名との違い）
4. 修飾すると、どの表の列かが明確になり解析も速くなる

</div>

```sql
SELECT e.last_name, department_name
FROM employees e JOIN departments d ON e.department_id = d.department_id;   -- ✅

SELECT employees.last_name
FROM employees e JOIN departments d ON e.department_id = d.department_id;   -- ❌ 別名を付けたのに表名

SELECT department_id
FROM employees e JOIN departments d ON e.department_id = d.department_id;   -- ❌ あいまい

SELECT e.last_name FROM employees AS e;                                     -- ❌ 表別名にASは不可
```

## 7-7 外部結合（ANSI構文） { #outer }

<div class="rule-box" markdown>

**判定基準**

1. `LEFT [OUTER] JOIN` … **FROMで先に書いた表（左）** の行をすべて残す
2. `RIGHT [OUTER] JOIN` … 後に書いた表（右）の行をすべて残す
3. `FULL [OUTER] JOIN` … 両方の行をすべて残す
4. `OUTER` は省略できる
5. 相手がない側の列は **NULL**

</div>

```sql
-- 部門に所属していない社員も表示
SELECT e.last_name, d.department_name
FROM employees e LEFT OUTER JOIN departments d
  ON e.department_id = d.department_id;

-- 社員がいない部門も表示
SELECT e.last_name, d.department_name
FROM employees e RIGHT JOIN departments d
  ON e.department_id = d.department_id;
```

---

## 7-8 Oracle独自構文の外部結合 (+) { #oracle-outer }

<div class="rule-box" markdown>

**判定基準**

1. `(+)` は **データが足りない側**（NULLで補われる側）の列に付ける
2. **両側に `(+)` は付けられない**（完全外部結合はできない、ORA-01468）
3. `(+)` を付けた条件を **OR で結ぶことはできない**。`IN` とも併用不可
4. ANSI構文（JOIN キーワード）と同じFROM句で混ぜない

</div>

```sql
-- 社員がいない部門も表示（employees側が足りない → e側に(+)）
SELECT e.last_name, d.department_name
FROM employees e, departments d
WHERE e.department_id(+) = d.department_id;     -- ✅ RIGHT JOIN 相当

WHERE e.department_id(+) = d.department_id(+);  -- ❌ 両側
```

!!! tip "(+) の向き"
    `(+)` を付けた側が「**NULLが補われる側**」、付けていない側が「**全行残る側**」です。
    `e.x = d.x(+)` なら e の全行が残る（LEFT JOIN 相当）。

## 7-9 自己結合 { #self }

<div class="rule-box" markdown>

**判定基準**

1. **同じ表を2回** FROMに書き、**別々の表別名** で区別する（表別名は必須）
2. 内部結合・外部結合・非等価結合の **どれでもよい**
3. ANSI構文・Oracle構文の **どちらでも書ける**
4. 結合キーの型や索引の有無に制限はない

</div>

```sql
-- 社員と上司の名前（上司がいない社員も表示するなら LEFT JOIN）
SELECT w.last_name AS worker, m.last_name AS manager
FROM employees w LEFT JOIN employees m
  ON w.manager_id = m.employee_id;
```

| 選択肢の言い回し | 判定 |
|---|---|
| 右側外部結合であってもよい | ✅ |
| 非等価結合であってもよい | ✅ |
| 内部結合であってもよい | ✅ |
| 結合キー列に指定できるのは索引列のみ | ❌ |
| 結合キー列に指定できるのはNUMBER型の列のみ | ❌ |

---

## 7-10 非等価結合 { #nonequi }

<div class="rule-box" markdown>

**判定基準**

1. `=` 以外の条件（`BETWEEN`、`>=`、`<` など）で結合する
2. ANSI構文なら **`ON` に条件を書く**（`USING`・`NATURAL` は等価結合専用なので不可）
3. Oracle構文（WHERE）でも書ける
4. 索引は不要

</div>

```sql
SELECT e.last_name, e.salary, g.grade_level
FROM employees e JOIN job_grades g
  ON e.salary BETWEEN g.lowest_sal AND g.highest_sal;    -- ✅
```

| 選択肢の言い回し | 判定 |
|---|---|
| USING句を使用する必要がある | ❌ |
| Oracle結合構文を使用する必要がある | ❌ |
| SQL:1999準拠のANSI結合構文を使用できる | ✅ |
| 結合キー列には索引を作成しておく必要がある | ❌ |

---

## 7-11 クロス結合 { #cross }

<div class="rule-box" markdown>

**判定基準**

1. 行数は **左の行数 × 右の行数**（WHEREで絞らない限り）
2. ANSI：`FROM a CROSS JOIN b`（`ON` は書けない）
3. Oracle：`FROM a, b` で結合条件を書かない
4. 結合条件を書き忘れた結合もデカルト積になる

</div>

```sql
SELECT name, dname FROM emp CROSS JOIN dept;                 -- ✅ 行数 = emp × dept
SELECT name, dname FROM emp CROSS JOIN dept ON emp.d = dept.d;  -- ❌ CROSS JOIN に ON は不可
```
