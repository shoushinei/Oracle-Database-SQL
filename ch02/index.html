    第2章 SELECTの基礎とデータの扱い¶

    この章で問われる形

    • 「正常に実行される問合せはどれですか」（列別名・DISTINCT・* の書き方）
    • 「列別名について正しい説明はどれですか」
    • 「NUMBER(p,s)の列に値を挿入します。正しい説明はどれですか」
    • 「DESCRIBEコマンド／DUAL表について正しい記述はどれですか」
    • 「算術演算子の優先順位について正しい記述はどれですか」

    2-1 SELECT文の基本構文と句の順序¶

    判定基準

    1. 句は必ずこの 記述順： SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY →（OFFSET/FETCH）
    2. SELECT と FROM は必須（Oracle 19c）。表がなければ FROM dual
    3. キーワード・表名・列名は大文字小文字を区別しない（二重引用符で囲んだ識別子を除く）
    4. 文は複数行に分けてよい。ただし キーワードを途中で分割・省略はできない

    内部の処理順（＝別名が使える場所の根拠）¶

    FROM → WHERE → GROUP BY → HAVING → SELECT（ここで列別名が決まる） → ORDER BY

    SELECT 句より 後 に処理される ORDER BY だけが列別名を使えます。→ 列別名

    細かい仕様

    Oracleは HAVING を GROUP BY より前に書いても受け付けます。ただし試験では上の順序を正として判断してください。

    * と他の列の併用¶

    SQL 判定 理由
    SELECT * FROM employees; ✅
    SELECT *, salary*12 FROM employees; ❌ * 単独の後に他の列は書けない
    SELECT salary, * FROM employees; ❌ 同上
    SELECT e.*, salary*12 FROM employees e; ✅ 表名.*／別名.* なら他の列と併用可

    2-2 列別名¶

    判定基準：書き方

    書き方 判定
    式 別名 ✅
    式 AS 別名 ✅
    式 "別名" ✅
    式 AS "別名" ✅
    式 '別名'（単一引用符） ❌

    判定基準：二重引用符なしで書ける別名の条件（1つでも外れたら "..." が必要）

    1. 先頭が 英字（数字・記号で始まらない）
    2. 使える文字は 英数字・_・$・# だけ（- や空白は不可）
    3. 予約語ではない（DATE SELECT FROM ORDER NUMBER TABLE など）
    4. 結果の列見出しは 大文字 に変換される（大小を保ちたいなら "..."）

    OK / NG例¶

    SELECT employee_id EMP_ID FROM employees;            -- ✅ 英数字と _
SELECT employee_id EMP$ID FROM employees;            -- ✅ $ も可
SELECT employee_id "EMP-ID" FROM employees;          -- ✅ 記号は "..." で囲む
SELECT salary*12 "Annual Salary" FROM employees;     -- ✅ 空白は "..." で囲む
SELECT hire_date "DATE" FROM employees;              -- ✅ 予約語は "..." で囲む

SELECT employee_id EMP-ID FROM employees;            -- ❌ - は使えない
SELECT employee_id AS EMP-ID FROM employees;         -- ❌ AS を付けても同じ
SELECT hire_date DATE FROM employees;                -- ❌ DATE は予約語
SELECT hire_date AS DATE FROM employees;             -- ❌ AS を付けても予約語は不可
SELECT employee_id 'EMP_ID' FROM employees;          -- ❌ 単一引用符は文字リテラル用
SELECT salary*12 Annual Salary FROM employees;       -- ❌ 空白を含むなら "..." が必要
SELECT salary*12 1year FROM employees;               -- ❌ 数字で始まる

    選択肢の見方

    「正常に実行される問合せ」で別名が複数ある選択肢は、すべての別名 が条件を満たすか確認します。 1つでも '...'、-、空白、予約語（引用符なし）があれば ❌ です。

    別名を使える句・使えない句¶

    句 列別名 理由
    ORDER BY ✅ SELECTより後に処理される
    WHERE ❌（ORA-00904） SELECTより前に処理される
    GROUP BY ❌ 同上
    HAVING ❌ 同上 
    SELECT salary*12 AS annual FROM employees ORDER BY annual;         -- ✅
SELECT salary*12 AS annual FROM employees WHERE annual > 100000;   -- ❌
SELECT salary*12 AS "Annual" FROM employees ORDER BY "Annual";     -- ✅ 引用符付き別名は同じ表記で
SELECT salary*12 AS "Annual" FROM employees ORDER BY annual;       -- ❌ 大小が違う（ANNUALを探してしまう）

    ひっかけ

    • 「別名を付けたら ORDER BY では 必ず 別名で指定する」→ ❌（列名・式・列位置でも指定できる）
    • 「別名には #、$ 以外の記号は どのような場合も 使えない」→ ❌（"..." で囲めば使える）
    • 「予約語を別名にするときは 単一引用符 で囲む」→ ❌（二重引用符）

    2-3 データ型¶

    判定基準

    型 ルール
    VARCHAR2(n) 可変長文字。サイズ指定が必須（VARCHAR2 だけは ❌）
    CHAR(n) 固定長文字。サイズ省略時は 1。足りない分は空白で埋める
    NUMBER(p,s) 数値。p=精度(1〜38)、s=位取り(-84〜127)。省略すると最大精度
    DATE 年・月・日・時・分・秒（小数秒なし・タイムゾーンなし）
    TIMESTAMP(n) DATE＋小数秒（n=0〜9、省略時6）
    CLOB / BLOB 大きな文字／バイナリ
    LONG 旧式の大きな文字。1表に1列まで、制約・索引・GROUP BY・ORDER BY・CTASでのコピー不可
    RAW(n) バイナリ（サイズ必須） 
    CREATE TABLE t1 (c1 VARCHAR2);          -- ❌ サイズがない
CREATE TABLE t1 (c1 VARCHAR2(10));      -- ✅
CREATE TABLE t1 (c1 CHAR);              -- ✅ CHAR(1) になる
CREATE TABLE t1 (c1 NUMBER);            -- ✅
CREATE TABLE t1 (c1 LONG, c2 LONG);     -- ❌ LONG は1表に1列まで

    日時の型の詳細は → 16章 日時データ型

    2-4 NUMBER(p,s) への格納¶

    判定基準

    1. 整数部に使える桁数 ＝ p − s。整数部がこれを超えると エラー（ORA-01438）
    2. 小数部が s 桁を超える分は 四捨五入して格納（エラーにならない）
    3. 四捨五入した 結果 が整数部の桁数を超えるならエラー
    4. NUMBER(p) は NUMBER(p,0)：小数は四捨五入して整数で格納

    NUMBER(5,2) の場合（整数部3桁・小数部2桁 → 最大 999.99）

    挿入する値 結果 理由
    123.45 ✅ 123.45
    123.456 ✅ 123.46 小数3桁目を四捨五入
    12.3456 ✅ 12.35 小数2桁に四捨五入
    1.23456 ✅ 1.23 小数2桁に四捨五入（1.2346 ではない）
    12345 ❌ 整数部5桁 > 3桁
    1234.5 ❌ 整数部4桁 > 3桁
    999.995 ❌ 四捨五入すると 1000.00 で整数部4桁

    ひっかけ

    「小数部の桁数が多いとエラーになる」→ ❌（四捨五入して格納される。エラーになるのは 整数部 があふれたとき）

    負の位取り

    NUMBER(5,-2) は百の位に丸めて格納します（12345 → 12300）。

    2-5 DESCRIBE コマンド¶

    判定基準

    1. DESC[RIBE] [スキーマ.]オブジェクト名 で 構造 を表示する
    2. 表示されるのは 列名・NULL可否（NOT NULL）・データ型 の3つだけ
    3. 対象：表・ビュー・シノニム、ファンクション／プロシージャ／パッケージ
    4. SQL*Plusコマンドだが SQL Developerでも使える。; は不要
    5. 表示されないもの：索引、NOT NULL以外の制約、デフォルト値、データ
    選択肢の言い回し 判定
    各列のデータ型を確認できる ✅
    SQL*PlusおよびSQL Developerから使用できる ✅
    索引が付いている列を確認できる ❌
    ビューの構造は表示できない ❌（表示できる）
    主キー列を確認できる ❌（NOT NULLとしか出ない）
    列のデフォルト値を確認できる ❌

    索引や制約は → 15章 データディクショナリ（USER_INDEXES、USER_CONSTRAINTS）

    2-6 DUAL表¶

    判定基準

    1. 所有者は SYS。すべてのユーザーが 特別な権限なしにアクセスできる
    2. 1列（DUMMY）・1行（値は 'X'）
    3. 表に依存しない式・関数の結果を 1行だけ 得たいときに使う
    SELECT SYSDATE FROM dual;           -- 1行返る
SELECT 10 * 3 FROM dual;            -- 1行返る
SELECT SYSDATE FROM employees;      -- ⚠️ エラーではない。employeesの行数分、同じ値が返る

    ひっかけ

    • 「DUAL表はDBAロールを持つユーザーのみアクセスできる」→ ❌
    • 「DUAL表のSELECT権限を付与されている必要がある」→ ❌（全ユーザーが使える）
    • 「1列持ち、0行 のデータが格納されている」→ ❌（1行）
    • 「SELECT SYSDATE FROM employees はエラーになる」→ ❌（行数分返る）

    2-7 算術演算子と優先順位¶

    判定基準

    1. 算術演算子は + - * / の4つ
    2. * / が + - より先
    3. 優先度が同じなら 左から右
    4. 優先順位を変えられるのは 丸かっこ ( ) だけ（[ ] { } は不可。|| は連結演算子）
    5. NULLを含む算術式の結果はNULL（NULLは優先順位には影響しない）
    6. ゼロ除算はエラー（ORA-01476）
    SELECT 12 * salary + 100   FROM employees;   -- (12*salary)+100
SELECT 12 * (salary + 100) FROM employees;   -- 先に足し算
SELECT 100 - 20 - 10       FROM dual;        -- 左から: (100-20)-10 = 70
SELECT 100 / 10 * 2        FROM dual;        -- 左から: (100/10)*2 = 20
SELECT salary * NULL       FROM employees;   -- すべて NULL
    選択肢の言い回し 判定
    ( )、[ ]、{ } で優先順位を変更できる ❌（( )のみ）
    NULLは式内の算術演算子の優先順位に影響を与える ❌（結果がNULLになるだけ）
    + と - のみの式では + が優先される ❌（同順位・左から右）
    優先度が等しい演算子は、カッコがない場合左から右に評価される ✅

    日付に対する算術は → 4章 日付演算

    2-8 文字リテラルと連結演算子¶

    判定基準

    1. 文字リテラル・日付リテラルは単一引用符 '...'。数値リテラルは引用符なし
    2. 文字リテラルの中身は 大文字小文字を区別 する（'King' ≠ 'KING'）
    3. 文字列中の ' は ''（2つ重ね） で表す
    4. 二重引用符 "..." は識別子（列名・別名）用。文字リテラルには使えない
    5. 連結演算子は ||。数値・日付も文字に変換されて連結される
    6. || でNULLを連結しても無視される（結果はNULLにならない）
    SELECT last_name || ' is ' || job_id FROM employees;     -- ✅
SELECT 'It''s ' || last_name FROM employees;             -- ✅ It's King
SELECT * FROM employees WHERE last_name = "King";        -- ❌ "King" は列名扱い（ORA-00904）
SELECT 'A' || NULL || 'B' FROM dual;                      -- ✅ 'AB'（NULLは無視）
SELECT 'A' + 'B' FROM dual;                               -- ❌ + は算術演算子（数値変換に失敗）

    ひっかけ

    • 算術式のNULLは結果をNULLにするが、連結のNULLは無視される。この違いがよく狙われます。
    • Oracleでは 空文字 '' はNULLとして扱われる。

    2-9 代替引用符（q演算子）¶

    判定基準

    1. 形は q'<区切り文字>文字列<区切り文字>'（q と ' の間に空白を入れない。Q でも可）
    2. 区切り文字が括弧なら 対応する閉じ括弧：[ ] { } ( ) < >
    3. 括弧以外の1文字（! # | など）なら 同じ文字 で閉じる
    4. 中の ' はそのまま書ける（重ねなくてよい）
    SELECT q'[It's a pen]' FROM dual;        -- ✅
SELECT q'{It's a pen}' FROM dual;        -- ✅
SELECT q'!It's a pen!' FROM dual;        -- ✅
SELECT q'[It's a pen' FROM dual;         -- ❌ 閉じる ] がない
SELECT q'[It's a pen}' FROM dual;        -- ❌ [ に対して } では閉じられない
SELECT q '[It's a pen]' FROM dual;       -- ❌ q と ' の間に空白

    2-10 NULLの性質¶

    判定基準

    1. NULLは「値がない・不明」。0でも空白でもない（ただし '' はNULLとして扱われる）
    2. 列にNULLが入るのは：INSERTで列を省略（DEFAULTなし）、NULL を明示、'' を指定
    3. 算術式 → 結果はNULL
    4. 連結 → 無視される
    5. 比較（= <> > など）→ 結果は「不明（UNKNOWN）」→ その行は返らない（エラーではない）
    6. NULLを探すのは IS NULL / IS NOT NULL だけ
    7. ソート → 最も大きい値として扱われる（昇順で最後）
    8. 集計関数 → COUNT(*) 以外はNULLを無視する

    詳しくは → 3章 NULL条件 / 3章 NULLのソート位置 / 5章 NULL関数 / 6章 集計とNULL

    2-11 DISTINCT¶

    判定基準

    1. DISTINCT は SELECT の直後に1回だけ 書ける
    2. DISTINCT は SELECTリスト全体の組合せ に対して重複を除く（特定の列だけには効かない）
    3. かっこ DISTINCT(列) と書いても、効果は 全体の組合せ に対して
    4. NULLどうしは重複とみなされ、1行にまとめられる
    5. DISTINCT を使うと、ORDER BY にはSELECTリストにある列・式しか書けない（ORA-01791）
    SELECT DISTINCT department_id FROM employees;                         -- ✅
SELECT DISTINCT department_id, job_id FROM employees;                 -- ✅ 組合せの重複を除く
SELECT DISTINCT department_id || ' : ' || job_id FROM employees;      -- ✅ 1つの式として重複除去
SELECT department_id, DISTINCT job_id FROM employees;                 -- ❌ SELECT直後ではない
SELECT DISTINCT department_id, DISTINCT job_id FROM employees;        -- ❌ 2回は書けない
SELECT DISTINCT department_id || DISTINCT job_id FROM employees;      -- ❌ 式の途中に書けない
SELECT DISTINCT(department_id), job_id FROM employees;                -- ⚠️ 実行できるが、組合せ全体で重複除去
SELECT DISTINCT job_id FROM employees ORDER BY salary;                -- ❌ SELECTにない列でソート不可

    「部門ごとに固有のジョブを表示したい」と聞かれたら

    「部門×ジョブの組合せの重複を除く」ことなので、SELECT DISTINCT department_id, job_id の形、 または両者を連結した1つの式を DISTINCT する形が該当します。

    ○×クイック判定¶

    記述 判定 ひとこと
    列別名には単一引用符を使える ❌ 二重引用符
    列別名に予約語を使うには二重引用符で囲む ✅

    列別名を付けたらORDER BYでは別名で指定しなければならない ❌ 列名・位置でも可
    列別名は二重引用符なしでも大文字小文字が保持される ❌ 大文字になる
    VARCHAR2はサイズを省略できる ❌ 必須
    NUMBER(5,2)に 1.23456 を入れると 1.2346 になる ❌ 1.23
    NUMBER(5,2)に 12345 を入れるとエラー ✅ 整数部あふれ
    DESCRIBEで索引を確認できる ❌
    DESCRIBEでビューの構造を表示できる ✅
    DUALは1列1行 ✅
    DUALはDBAのみアクセスできる ❌ 全ユーザー
    ( ) [ ] { } で演算子の優先順位を変更できる ❌ ( )のみ
    同じ優先度の演算子は左から右に評価される ✅
    NULLを含む算術式の結果はNULL ✅
    NULLを || で連結すると結果はNULL ❌ NULLは無視
    SELECT a, DISTINCT b は実行できる ❌ SELECT直後のみ
    DISTINCTはSELECTリストの最初の列にだけ効く ❌ 組合せ全体
